# 12장 데이터를 다루는 일

<sub>2부 데이터와 수의 최소한 · 표제어 42개 · 도해 3개</sub>

> **여는 지도** — 이 장의 낱말 마흔둘. 원본에서 학습 준비까지 여섯 자리

이 장은 수학이 아니라 손이 가는 일을 다룬다. 그리고 실제로 모델 성능을 가르는 자리의 절반이 여기 있다.

같은 구조와 같은 학습 절차로 두 사람이 만든 모델의 성능이 크게 다르면 원인은 대개 데이터다. 무엇을 모았고, 어떻게 정리했고, 어디서 잘랐는가. 논문에 안 적히고 재현이 안 되는 부분도 대부분 이쪽이다.

10장의 표본 이야기가 여기서 실무가 된다. 학습 데이터는 세상의 표본이고, 그 표본이 치우쳐 있으면 모델이 그 치우침을 그대로 배운다. 그리고 25장에서 이 이야기가 다시 나온다. 사전학습 데이터를 어떻게 섞는지가 모델의 성격을 정한다. 45장의 데이터 플라이휠도 결국 이 장의 절차를 계속 도는 일이다.

## 한눈에 보기

| 무리 | 무엇을 다루나 | 어디서 다시 쓰나 |
|---|---|---|
| 모으고 정리하기 | 원본을 쓸 수 있는 상태로 | 25장 코퍼스 |
| 라벨 붙이기 | 정답을 사람이 적는 일 | 26장 선호 데이터 |
| 나누기 | 학습과 평가를 가르는 선 | 15장, 42장 |
| 늘리고 바꾸기 | 모자란 데이터를 메우는 법 | 45장 합성 데이터 |
| 기록하기 | 무엇을 썼는지 남기는 일 | 48장, 49장 |


## 표제어

### 모으고 정리하기

#### 데이터 수집

<sub>Data Collection</sub>

**학습이나 분석에 쓸 데이터를 모으는 일.**

<sub>관련어 크롤링, 라이선스, 로그, 편향(10장), 데이터 권리(48장에서 다룬다)</sub>

- **크롤링** `Crawling` — 웹을 자동으로 돌며 문서를 모으는 일. 사이트가 허용 범위를 적어 둔 파일 (robots.txt)을 따르는 것이 관행이고, 강제력은 없다.
- **로그** `Log` — 시스템이 남기는 동작 기록. 공짜로 쌓이지만 그 자체로는 학습에 못 쓴다. 43장에서 다시 나온다.
- **라이선스** `License` — 그 데이터를 어떤 조건으로 쓸 수 있는지 적은 것. 학습에 써도 되는지가 따로 적혀 있지 않은 경우가 많아 해석이 갈린다.
- **데이터 정제** `Data Cleaning` — 잘못되거나 쓸 수 없는 데이터를 고치거나 걸러 내는 일. <sub>관련어 결측, 중복 제거, 이상치(10장), 표준화</sub>
- **결측** `Missing Value` — 값이 비어 있는 자리. 버릴지, 평균으로 채울지, 비었다는 사실 자체를 항목으로 만들지 정해야 한다.
- **중복 제거** `Deduplication` — 같거나 거의 같은 데이터를 걸러 내는 일. 25장에서 이것을 제대로 안 하면 같은 문서를 여러 번 학습해 특정 문장을 통째로 외우게 된다.
- **표준화** `Standardization` — 값을 평균 0과 표준편차 1로 맞추는 일. 항목마다 단위가 다를 때 필요하다.
- **최소최대 정규화** `Min-Max Normalization` — 값을 0과 1 사이로 눌러 담는 일. 극단값이 있으면 나머지가 한쪽에 몰린다.
- **개인정보 제거** `PII Removal` — 이름과 전화번호처럼 개인을 알아볼 수 있는 정보 (PII)를 지우거나 가리는 일. 완전히 못 지우는 경우가 있어서 48장에서 문제가 된다.

### 이름표를 붙이는 일

#### 라벨링

<sub>Labeling</sub>

**데이터마다 정답을 사람이 적어 붙이는 일.**

<sub>관련어 어노테이션, 라벨 지침, 일치도, 선호 데이터(26장에서 다룬다)</sub>

- **어노테이션** `Annotation` 〔유동〕 — 데이터에 표시를 붙이는 일. 라벨링과 거의 같은 뜻으로 쓰이고, 구간 표시처럼 더 세밀한 작업을 가리키기도 한다.
- **라벨 지침** `Annotation Guideline` — 어떤 경우에 어떤 라벨을 붙일지 적은 문서. 이 문서의 품질이 데이터 품질을 정한다.
- **일치도** `Inter-Annotator Agreement` — 여러 사람이 같은 데이터에 같은 라벨을 붙인 비율. 아무렇게나 찍어도 우연히 맞는 몫이 있어서, 그 몫을 빼고 재는 카파 계수를 쓴다.
- **금 표준** `Gold Standard` — 믿을 만하다고 정한 정답 집합. 42장의 골든셋과 같은 발상이다.
- **약한 라벨** `Weak Label` — 규칙이나 다른 모델로 대충 붙인 라벨. 싸고 부정확하며, 양으로 메우는 방식이다.
- **능동 학습** `Active Learning` — 모델이 헷갈려 하는 데이터를 골라 사람에게 라벨을 요청하는 방식. 라벨 비용을 줄인다.
- **라벨 노이즈** `Label Noise` — 잘못 붙은 정답. 일정 비율까지는 학습이 견디지만, 특정 종류에 몰려 있으면 그 종류를 통째로 잘못 배운다.

### 나누는 선

#### 데이터 분할

<sub>Data Splitting</sub>

**가진 데이터를 학습용과 검증용과 시험용으로 나누는 일.**

<sub>관련어 학습 집합, 검증 집합, 시험 집합, 누수, 교차검증(15장에서 다룬다)</sub>

- **학습 집합** `Training Set` — 모델의 가중치를 맞추는 데 쓰는 데이터.
- **검증 집합** `Validation Set` — 설정을 고르고 언제 멈출지 정하는 데 쓰는 데이터. 개발 집합이라고도 부른다.
- **시험 집합** `Test Set` — 마지막에 한 번만 쓰는 데이터. 여러 번 보면 이미 시험 집합이 아니다.
- **데이터 누수** `Data Leakage` — 학습해서는 안 될 정보가 학습 데이터에 섞여 들어가는 일. <sub>관련어 데이터 분할, 벤치마크 오염(42장에서 다룬다), 시간 누수</sub>
- **시간 누수** `Temporal Leakage` — 미래의 정보로 과거를 맞히게 되는 문제. 시간 순서가 있는 데이터를 무작위로 나눌 때 생긴다.
- **층화 추출** `Stratified Sampling` — 각 부류의 비율을 유지하며 나누는 방식. 드문 부류가 한쪽에만 몰리는 것을 막는다.
- **홀드아웃** `Holdout` — 한 덩어리를 떼어 두고 평가에만 쓰는 방식. 가장 단순한 분할이다.

### 늘리고 바꾸기

- **데이터 증강** `Data Augmentation` — 가진 데이터를 조금씩 바꿔서 개수를 늘리는 일. <sub>관련어 합성 데이터(45장에서 다룬다), 불균형, 재표집</sub>
- **특징 공학** `Feature Engineering` — 원본 데이터에서 모델이 쓰기 좋은 항목을 사람이 만들어 내는 일. <sub>관련어 특징, 표현 학습(17장에서 다룬다), 피처 스토어</sub>
- **특징** `Feature` 〔유동〕 — 모델에 넣는 입력 항목 하나. 4부에서는 모델이 내부에서 만든 표현을 가리키기도 해서 뜻이 넓어진다.
- **피처 스토어** `Feature Store` — 학습과 서빙에서 같은 방식으로 만든 특징을 꺼내 쓰게 모아 둔 저장소. 학습과 실제 사용의 계산이 어긋나는 문제를 막는다.
- **원핫 인코딩** `One-Hot Encoding` — 부류를 자리 하나만 1인 벡터로 바꾸는 방식. 부류가 많으면 벡터가 매우 길어진다.
- **범주형 인코딩** `Categorical Encoding` — 글자로 된 부류를 수로 바꾸는 여러 방법. 순서가 없는 것에 번호를 매기면 없는 순서를 만들어 낸다.
- **클래스 불균형** `Class Imbalance` — 맞혀야 할 부류들의 개수가 크게 차이 나는 상태. <sub>관련어 재표집, 정밀도와 재현율(15장에서 다룬다), 데이터 증강</sub>
- **재표집** `Resampling` — 적은 쪽을 복제하거나 많은 쪽을 덜어 내 비율을 맞추는 일. 복제하면 그 데이터에 과하게 맞춰질 수 있다.
- **클래스 가중치** `Class Weight` — 드문 부류의 오차에 더 큰 무게를 주는 방식. 데이터를 안 건드리고 균형을 맞춘다.

### 무엇을 썼는지 기록하기

**데이터에 대해 남겨야 하는 것**

| 항목 | 무엇을 적나 | 왜 필요한가 |

|---|---|---|

| 출처 | 어디서 어떻게 가져왔나 | 권리 확인과 재현 |

| 기간 | 언제부터 언제까지의 데이터인가 | 낡았는지 판단 |

| 전처리 | 무엇을 걸러 내고 무엇을 고쳤나 | 결과 해석 |

| 라벨 절차 | 누가 어떤 지침으로 붙였나 | 품질 판단 |

| 알려진 한계 | 어떤 경우가 빠져 있나 | 안 되는 자리 예측 |

| 버전 | 어느 시점의 데이터인가 | 재현과 비교 |

이 여섯을 적어 놓은 문서를 데이터 카드라고 부른다.
49장의 모델 카드와 같은 발상이고, 규제 논의에서 요구 항목으로 올라와 있다.

- **데이터 카드** `Data Card` — 어떤 데이터인지 정리해 붙이는 문서. 데이터시트라고도 부른다.
- **데이터 계보** `Data Lineage` — 어떤 데이터가 어디서 와서 어떤 처리를 거쳤는지의 경로. 문제가 생겼을 때 거슬러 올라가는 데 쓴다.
- **데이터 버전 관리** `Data Versioning` — 데이터의 상태를 버전으로 남기는 일. 코드만 버전 관리하면 같은 코드가 다른 결과를 내는 이유를 못 찾는다.
- **재현성** `Reproducibility` — 같은 절차로 같은 결과가 나오는 성질. 데이터 버전과 시드와 라이브러리 버전이 다 맞아야 성립한다.
- **데이터 드리프트** `Data Drift` — 시간이 지나며 입력 데이터의 분포가 바뀌는 것. 모델을 안 바꿔도 성능이 떨어진다.
- **ETL 파이프라인** `ETL Pipeline` — 데이터를 꺼내고 바꾸고 넣는 자동화된 흐름. 5장에서 나온 낱말이 여기서는 학습 준비 절차가 된다.
- **데이터 품질** `Data Quality` 〔유동〕 — 데이터가 목적에 맞게 정확하고 완전하고 일관된 정도. 무엇을 품질로 볼지가 과제마다 달라 기준이 흔들린다.

## 자주 헷갈리는 짝

- **검증 집합과 시험 집합** 같은 점은 둘 다 학습에 안 쓴다는 것.
다른 점은 몇 번 보는가다. 검증은 여러 번 보고 시험은 마지막에 한 번 본다.
- **정제와 증강** 같은 점은 둘 다 데이터를 손본다는 것.
다른 점은 방향이다. 앞은 덜어 내고 뒤는 늘린다.
- **데이터 누수와 오염** 같은 점은 둘 다 평가를 부풀린다는 것.
다른 점은 층이다. 앞은 한 프로젝트 안의 문제이고 뒤는 공개 벤치마크가 학습에 섞인 문제다.
- **라벨과 특징** 같은 점은 둘 다 데이터의 항목이라는 것.
다른 점은 역할이다. 특징은 입력이고 라벨은 맞혀야 할 답이다.
- **표준화와 정규화** 같은 점은 둘 다 값의 범위를 맞춘다는 것.
다른 점은 기준이다. 앞은 평균과 표준편차, 뒤는 최솟값과 최댓값이다.

## 지금 움직이는 것

데이터 쪽 무게중심이 양에서 출처로 옮겨 갔다. 많이 모으는 경쟁이 한동안 이어지다가, 권리와 출처가 문제가 되면서 어디서 왔는지 밝힐 수 있는 데이터의 값이 올라갔다. 동시에 모델이 만든 데이터를 학습에 쓰는 비중이 늘고 있어서, 사람이 만든 것과 모델이 만든 것을 구분해 기록하는 일이 새 과제가 되었다. 45장에서 이 이야기를 다시 다룬다.

## 더 볼 곳

여기서 나눈 학습과 시험 집합이 15장의 평가 절차로 이어진다. 분포 이동은 16장에서, 데이터 카드는 49장에서 다시 나온다. 합성 데이터와 플라이휠은 45장이 통째로 다룬다. 이것으로 2부가 끝난다.
