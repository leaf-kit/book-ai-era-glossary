# 24장 어텐션의 변주와 긴 문맥

<sub>5부 언어 모델의 해부 · 표제어 37개 · 도해 4개</sub>

> **여는 지도** — 이 장의 낱말 서른일곱. 길이가 늘어날 때 생기는 네 가지 문제와 대책

이 장은 23장의 어텐션이 길이가 늘어날 때 부딪히는 문제와 그 대책을 다룬다. 지난 몇 해 동안 가장 많은 낱말이 새로 생긴 자리다.

문제가 넷이고 서로 다르다. 계산량이 길이의 제곱으로 늘고, 생성할 때 들고 있어야 할 메모리가 길이에 비례해 늘고, 학습할 때 본 것보다 긴 입력이 들어오면 위치를 모르고, 길게 넣을 수 있게 되어도 모델이 그 안의 정보를 고르게 쓰지 못한다.

넷을 섞어 말하는 일이 흔하다. 문맥 창이 백만 토큰이라는 말과 백만 토큰을 실제로 잘 쓴다는 말은 다르다. 앞은 넣을 수 있다는 뜻이고 뒤는 그 안에서 필요한 것을 찾아낸다는 뜻이다. 이 장이 그 둘을 갈라 놓는다.

## 한눈에 보기

| 무리 | 어떤 문제인가 | 어디서 다시 쓰나 |
|---|---|---|
| 계산 비용 | 길이의 제곱으로 는다 | 44장 비용 |
| 메모리 비용 | 생성 중에 계속 쌓인다 | 41장 서빙 |
| 위치 처리 | 학습보다 긴 것을 다루기 | 25장 문맥 확장 |
| 실효 활용 | 넣어도 잘 못 쓴다 | 32장 컨텍스트 |
| 대체 구조 | 어텐션 말고 다른 방법 | 51장 경향 |


## 표제어

### 계산이 제곱으로 느는 문제

#### 이차 비용

<sub>Quadratic Cost</sub>

**어텐션의 계산량과 메모리가 시퀀스 길이의 제곱에 비례해 늘어나는 성질.**

<sub>관련어 플래시 어텐션, 희소 어텐션, 빅오 표기(6장), 어텐션(23장)</sub>

- **플래시 어텐션** `FlashAttention` — 어텐션의 중간 결과를 메모리에 다 쓰지 않고 조각으로 나눠 계산해 메모리 접근을 크게 줄인 방법. <sub>관련어 이차 비용, 메모리 대역폭(2장), 캐시(2장), 커널 (GPU)(2장)</sub>
- **희소 어텐션** `Sparse Attention` — 모든 자리를 보지 않고 일부만 보게 제한한 어텐션. 계산이 줄고 못 보는 관계가 생긴다.
- **슬라이딩 윈도우 어텐션** `Sliding Window Attention` — 자기 근처의 정해진 개수만 보는 방식. 층을 쌓으면 간접적으로 넓게 본다. 19장의 수용영역과 같은 발상이다.
- **전역 토큰** `Global Token` — 모두가 보고 모두를 보는 특별한 자리. 희소 어텐션에서 멀리 떨어진 정보를 잇는 통로로 둔다.
- **선형 어텐션** `Linear Attention` — 소프트맥스를 근사해 계산을 길이에 비례하게 만든 방식들. 비용이 줄고 품질이 떨어지는 경우가 보고된다.
- **블록 희소** `Block Sparse` — 자리를 블록으로 묶고 블록 단위로 볼지 말지 정하는 방식. 가속기에서 실제로 빨라지도록 만든 형태다.

### 메모리가 계속 쌓이는 문제

#### KV 캐시

<sub>KV Cache</sub>

**생성 중에 앞서 계산한 키와 값을 들고 있다가 다시 쓰는 저장 공간.**

갈리는 자리 — 메모리 관리까지 포함해 부르는 사람과 저장된 배열 자체만 가리키는 사람이 갈린다

<sub>관련어 MQA, GQA, 페이지드 어텐션, 배칭(41장에서 다룬다), 문맥 창</sub>

- **MQA** `Multi-Query Attention` — 모든 헤드가 키와 값을 하나로 공유하는 방식. KV 캐시가 헤드 수만큼 줄고 품질이 조금 떨어진다.
- **GQA** `Grouped-Query Attention` — 헤드를 몇 무리로 나누고 무리마다 키와 값을 공유하는 방식. 앞의 둘 사이 절충이고 지금 널리 쓰인다.
- **MLA** `Multi-head Latent Attention` 〔신조〕 — 키와 값을 낮은 차원으로 압축해 캐시에 담는 방식. 캐시를 크게 줄이려는 최근 설계다. <sub>생긴 때: 2024년 무렵 제안되었다</sub>
- **캐시 축출** `Cache Eviction` — 오래되었거나 덜 중요한 키와 값을 버려 메모리를 확보하는 일. 무엇을 버릴지 고르는 기준이 품질을 정한다.
- **페이지드 어텐션** `PagedAttention` — KV 캐시를 3장의 가상 메모리처럼 작은 페이지로 나눠 관리하는 방식. 조각남을 줄여 같은 메모리로 더 많은 요청을 받는다.
- **KV 캐시 양자화** `KV Cache Quantization` — 캐시를 낮은 정밀도로 담아 메모리를 줄이는 방법. 28장의 양자화를 캐시에 적용한 것이다.
- **프리필** `Prefill` — 미리 채운다는 뜻이고, 입력을 한꺼번에 통과시켜 KV 캐시를 채워 두는 단계다. 병렬로 계산되어 계산이 병목이다.
- **디코드** `Decode` — 토큰을 하나씩 만드는 단계. 병렬이 안 되고 대역폭이 병목이다. 41장에서 이 둘을 나눠 다루는 이야기가 나온다.
- **프리필과 디코드의 비대칭** `Prefill-Decode Asymmetry` — 입력을 읽는 단계와 답을 만드는 단계의 성질이 완전히 다른 것. <sub>관련어 프리필, 디코드, 연속 배칭(41장에서 다룬다), 첫 토큰 지연(44장에서 다룬다)</sub>

### 학습보다 긴 것이 들어올 때

#### 문맥 창

<sub>Context Window</sub>

**모델이 한 번에 받을 수 있는 토큰의 최대 개수.**

<sub>관련어 토큰(22장), 실효 문맥, KV 캐시, 문맥 예산(32장에서 다룬다)</sub>

- **위치 외삽** `Position Extrapolation` — 학습할 때 본 길이보다 긴 입력에서도 위치 정보가 동작하게 만드는 일. <sub>관련어 로프(22장), 위치 보간, 문맥 확장 학습, 위치 인코딩(22장)</sub>
- **위치 보간** `Position Interpolation` — 긴 입력의 위치 값을 학습 범위 안으로 눌러 담는 방법. 간단하고 짧은 입력의 성능이 조금 떨어질 수 있다.
- **문맥 확장 학습** `Context Extension Training` — 긴 데이터로 짧게 추가 학습해 문맥 창을 늘리는 절차. 지금 긴 문맥 모델을 만드는 표준 방식이다.
- **길이 일반화** `Length Generalization` — 학습에서 본 길이를 넘어서도 동작하는 성질. 구조와 위치 인코딩 방식이 이 성질을 크게 가른다.

### 길게 넣어도 잘 못 쓰는 문제

#### 중간 손실 〔유동〕

<sub>Lost in the Middle</sub>

**긴 입력에서 앞부분과 뒷부분은 잘 쓰는데 가운데 있는 정보를 놓치는 현상.**

갈리는 자리 — 어느 모델에서 얼마나 나타나는지가 시험 설정에 크게 좌우되어 결과가 엇갈린다

<sub>관련어 실효 문맥, 건초더미 시험, 문맥 예산(32장에서 다룬다), 재순위(33장에서 다룬다)</sub>

- **실효 문맥** `Effective Context` 〔신조〕 — 선언된 문맥 창 중에서 모델이 실제로 쓸모 있게 활용하는 범위. <sub>갈리는 자리: 재는 방법이 합의되지 않아 어느 값을 실효 문맥이라 부를지가 다르다 · 생긴 때: 2023년 이후 긴 문맥 모델이 나오면서 쓰이기 시작했다 · 관련어 중간 손실, 건초더미 시험, 문맥 창</sub>
- **건초더미 시험** `Needle in a Haystack` — 건초더미에서 바늘 찾기라는 말에서 온 이름이고, 긴 문서 안에 문장 하나를 숨겨 놓고 찾아내는지 보는 시험이다. 통과하기 쉬워서 이것만으로 긴 문맥 능력을 판단하면 안 된다는 지적이 있다.
- **다중 근거 시험** `Multi-hop Retrieval Test` 〔신조〕 — 긴 입력 안에서 여러 조각을 이어 붙여야 답이 되는 시험. 단순 찾기보다 훨씬 어렵다. <sub>생긴 때: 2024년 무렵부터 긴 문맥 평가에 쓰인다</sub>
- **주의 분산** `Distraction` — 비슷하지만 틀린 근거가 섞여 있을 때 그쪽을 따라가는 현상. 33장의 검색 품질과 직결된다.

### 어텐션 말고 다른 방법

**긴 문맥을 다루는 다섯 갈래**

| 갈래 | 어떻게 하나 | 내주는 것 |

|---|---|---|

| 정확한 어텐션 최적화 | 계산은 그대로, 메모리 접근을 줄인다 | 없다 |

| 희소화 | 볼 자리를 줄인다 | 못 보는 관계 |

| 선형화 | 계산 구조를 바꾼다 | 품질 |

| 상태공간 | 상태에 요약해 나른다 | 정확한 회상 |

| 바깥에 두기 | 검색으로 필요한 것만 넣는다 | 검색 품질에 의존 |

마지막 줄이 33장의 RAG다. 문맥을 늘리는 대신 밖에 두고 필요할 때 가져온다.
긴 문맥이 싸지면 검색이 필요 없어진다는 주장과, 문서가 아무리 늘어도
전부 넣을 수는 없다는 주장이 맞서 있다. 33장에서 이 논쟁을 다시 다룬다.

- **상태공간 모델** `State Space Model, SSM` 〔신조〕 — 상태를 이어 가며 시퀀스를 처리하되 학습 때는 병렬로 계산되게 만든 구조. <sub>갈리는 자리: 어느 계열까지 이 이름으로 묶을지가 문서마다 다르다 · 생긴 때: 2021년 무렵 제안되었고 2023년 이후 이름이 널리 쓰인다 · 관련어 RNN(20장), 하이브리드 구조 (시퀀스), KV 캐시, 선형 어텐션</sub>
- **하이브리드 구조 (시퀀스)** `Hybrid Architecture` 〔신조〕 — 어텐션 층과 상태를 이어 가는 층을 섞어 쌓은 구조. 비용과 회상 능력을 절충한다. <sub>생긴 때: 2024년 무렵부터 실제 모델에 쓰이기 시작했다</sub>
- **순환 메모리** `Recurrent Memory` — 긴 입력을 조각으로 나눠 처리하며 요약 상태를 다음 조각에 넘기는 방식. 문맥 창을 넘는 입력을 다루는 오래된 접근이다.
- **메모리 토큰** `Memory Token` — 앞의 내용을 요약해 담아 두는 특별한 토큰 자리. 압축한 문맥을 계속 들고 가려는 시도다.
- **압축 문맥** `Context Compression` 〔신조〕 — 긴 문맥을 요약하거나 줄여서 넣는 방법들의 총칭. 32장에서 실무 관점으로 다시 다룬다. <sub>생긴 때: 2023년 이후 쓰이기 시작했다</sub>

### 길이에 관한 실무 감각

**길이를 두 배로 늘리면 무엇이 몇 배가 되나**

| 항목 | 늘어나는 정도 | 누가 부담하나 |

|---|---|---|

| 입력 요금 | 두 배 | 사용자 |

| 어텐션 계산 | 네 배 | 프리필 시간 |

| 피드포워드 계산 | 두 배 | 프리필 시간 |

| KV 캐시 메모리 | 두 배 | 동시 요청 수 |

| 첫 토큰 지연 | 두 배에서 네 배 사이 | 체감 속도 |

| 토큰당 생성 속도 | 조금 느려진다 | 체감 속도 |

실제 비율은 구현과 길이 구간에 따라 다르다.
짧은 구간에서는 피드포워드가 지배해 두 배에 가깝고,
아주 길어지면 어텐션이 지배해 네 배에 가까워진다.

- **입력 토큰과 출력 토큰** `Input and Output Tokens` — 요금이 따로 매겨지고 대개 출력이 몇 배 비싸다. 만드는 단계가 병렬이 안 되기 때문이다.
- **문맥 재사용** `Context Reuse` — 같은 앞부분을 여러 요청이 공유해 캐시를 다시 쓰는 일. 44장의 프롬프트 캐시가 이것이다.
- **청크 프리필** `Chunked Prefill` — 긴 입력을 조각으로 나눠 읽으며 다른 요청의 생성과 번갈아 처리하는 방식. 한 요청이 서버를 오래 잡는 것을 막는다.
- **어텐션 비율** `Attention Fraction` — 전체 계산에서 어텐션이 차지하는 비중. 길이가 짧으면 작고 길어지면 지배적이 된다.
- **배치와 길이의 곱** `Batch-Length Product` — 동시에 처리하는 요청 수와 각 요청의 길이를 곱한 값. 이 값이 메모리 한계를 정한다.

## 자주 헷갈리는 짝

- **문맥 창과 실효 문맥** 같은 점은 둘 다 길이를 나타낸다는 것.
다른 점은 넣을 수 있는가와 실제로 쓰는가다. 광고에 나오는 숫자는 앞쪽이다.
- **KV 캐시와 프롬프트 캐시** 같은 점은 둘 다 계산을 아낀다는 것.
다른 점은 범위다. 앞은 한 요청 안이고 뒤는 요청 사이에 재사용한다.
- **플래시 어텐션과 희소 어텐션** 같은 점은 둘 다 어텐션을 빠르게 한다는 것.
다른 점은 결과가 같은가다. 앞은 정확히 같고 뒤는 근사다.
- **프리필과 디코드** 같은 점은 둘 다 추론의 일부라는 것.
다른 점은 병목이다. 앞은 계산, 뒤는 대역폭이다.
- **MQA와 GQA** 같은 점은 둘 다 키와 값을 공유해 캐시를 줄인다는 것.
다른 점은 공유 정도다. GQA가 무리로 나눈 절충이다.

## 지금 움직이는 것

문맥 창 숫자 경쟁이 한 차례 지나가고, 지금은 그 안을 얼마나 실제로 쓰는지로 논의가 옮겨 갔다. 백만 토큰을 넣을 수 있는 모델이 나왔지만 그 길이에서의 정확도와 비용이 실용적인지는 과제마다 다르다. 동시에 어텐션을 부분적으로 다른 구조로 바꾸는 시도가 실제 제품에 들어가기 시작했다.

## 더 볼 곳

여기서 나온 프리필과 디코드가 41장의 서빙 설계로 이어진다. 문맥을 무엇으로 채울지는 32장이고, 밖에 두고 가져오는 방식은 33장이다.
