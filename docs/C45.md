# 45장 데이터 플라이휠

<sub>8부 만들고 운영하기 · 표제어 50개 · 도해 3개</sub>

> **여는 지도** — 이 장의 낱말 쉰. 쓰면서 좋아지는 고리가 도는 여섯 자리

이 장은 쓰면서 좋아지게 만드는 고리를 다룬다. 8부의 마지막 장이고, 앞의 네 장이 만든 것들을 하나로 잇는다.

고리가 도는 방식은 단순하다. 쓰이면서 기록이 쌓이고, 그중 쓸 만한 것을 골라 데이터로 만들고, 그 데이터로 시스템을 고치고, 좋아졌는지 확인한다. 이것이 돌면 시간이 갈수록 나아지고, 안 돌면 처음 상태에 머문다.

무엇을 고칠지가 여러 층이다. 프롬프트를 고치는 것이 가장 싸고 빠르고, 검색 자료를 보강하는 것이 그다음이고, 모델을 다시 학습시키는 것이 가장 비싸다. 대부분의 개선이 위의 둘에서 나온다.

48장의 문제가 이 장 전체에 깔려 있다. 사용자 데이터를 학습에 쓰려면 동의가 있어야 하고, 동의가 없으면 이 고리의 아래쪽 절반이 안 돈다.

|---|---|---|

| 권리 | 써도 되는 데이터인가 | 48장 권리 |


## 표제어

### 고리 전체

#### 데이터 플라이휠 〔유동〕

<sub>Data Flywheel</sub>

**쓰이면서 쌓인 데이터로 시스템을 고치고, 좋아진 시스템이 더 쓰이며 데이터가 더 쌓이는 순환.**

갈리는 자리 — 저절로 좋아진다는 뜻으로 과장되게 쓰이는 경우가 많다

<sub>관련어 사용 로그(43장), 피드백 수집, 골든셋(42장), 재학습</sub>

- **개선 고리** `Improvement Loop` — 고치고 확인하기를 반복하는 절차. 도는 주기가 짧을수록 빨리 좋아진다.
- **고리 주기** `Cycle Time` — 한 바퀴 도는 데 걸리는 시간. 프롬프트는 하루, 미세조정은 몇 주가 걸린다.
- **선순환** `Virtuous Cycle` 〔유동〕 — 좋아진 것이 더 좋아질 조건을 만드는 순환. 실제로 성립하려면 각 단계가 자동으로 이어져야 한다.

### 무엇이 좋고 나빴는지 알아내기

**신호의 네 가지 출처**

| 출처 | 무엇 | 양 | 믿을 만함 |

|---|---|---|---|

| 명시 피드백 | 좋아요와 싫어요 | 적다 | 치우쳐 있다 |

| 암묵 신호 | 복사, 재질문, 이탈 | 많다 | 해석이 필요 |

| 사람 수정 | 답을 고쳐서 쓴 흔적 | 중간 | 매우 좋다 |

| 자동 검사 | 형식 오류, 실행 실패 | 많다 | 확실하다 |

세 번째가 가장 값지다. 사람이 어떻게 고쳤는지는
무엇이 문제였고 무엇이 맞는지를 동시에 알려 준다.
그것을 수집할 수 있는 제품 구조를 만드는 것이 이 장의 실무적 요령이다.

- **피드백 수집** `Feedback Collection` — 무엇이 좋고 나빴는지 알려 주는 신호를 모으는 일. <sub>관련어 명시 피드백, 암묵 신호, 사람 수정, 사용자 피드백(42장)</sub>
- **명시 피드백** `Explicit Feedback` — 사용자가 직접 누른 평가. 양이 적고 극단에 몰린다.
- **사람 수정** `Human Edit` — 답을 사람이 고쳐서 쓴 기록. 가장 정보량이 많은 신호다.
- **재질문** `Rephrase Rate` — 같은 것을 다시 물어본 비율. 답이 만족스럽지 않았다는 강한 신호다.
- **이탈** `Abandonment` — 답을 받고 아무것도 안 하고 나간 것. 해석이 갈려서 다른 신호와 같이 봐야 한다.
- **신고** `Report` — 문제가 있는 답을 사용자가 알린 것. 46장과 47장의 사례를 모으는 통로다.
- **자동 검사 실패** `Automated Check Failure` — 형식 오류나 실행 실패처럼 기계가 잡아낸 문제. 가장 확실한 신호이고 자동으로 쌓인다.
- **신호 희소성** `Feedback Sparsity` — 신호가 드물어 통계로 쓰기 어려운 상태. 대부분의 요청에 아무 신호가 없다.

### 신호를 데이터로 만들기

- **데이터 선별** `Data Curation` — 쌓인 기록에서 쓸 만한 것을 골라 데이터로 다듬는 일. <sub>관련어 라벨링(12장), 능동 학습(12장), 실패 사례(42장), 데이터 품질(12장)</sub>
- **사례 선별** `Case Selection` — 어떤 기록을 데이터로 쓸지 고르는 일. 무작위로 뽑는 것보다 실패와 경계 사례를 고르는 편이 낫다.
- **경계 사례** `Edge Case` — 판단이 애매한 사례. 여기서 배우는 것이 가장 많다.
- **사람 검토** `Human Review` — 선별한 사례를 사람이 확인하고 정답을 붙이는 일. 비용이 들고 품질을 정한다.
- **선호 데이터 만들기** `Preference Data Creation` — 같은 질문에 여러 답을 만들고 사람이 고르게 하는 것. 26장의 정렬 재료가 된다.
- **평가 사례로 승격** `Promote to Eval` — 실패 사례를 평가 집합에 넣는 것. 학습에 쓰기 전에 이것부터 하는 것이 순서다.
- **동의 확인** `Consent Check` — 그 데이터를 학습에 써도 되는지 확인하는 절차. 48장의 요건이고 안 하면 나중에 되돌릴 수 없다.
- **개인정보 제거 (플라이휠)** `PII Scrubbing` — 학습에 넣기 전에 식별 정보를 지우는 일. 완전히 못 지우는 경우가 있어 검토가 필요하다.

### 모델로 데이터를 만들기

#### 합성 데이터 〔신조〕

<sub>Synthetic Data</sub>

**모델이 만들어 낸 데이터를 학습이나 평가에 쓰는 것.**

갈리는 자리 — 어디까지를 합성으로 볼지가 다르다. 사람이 손본 것을 포함하기도 한다

생긴 때 — 2023년 이후 널리 쓰인다

<sub>관련어 증류(28장), 모델 붕괴, 데이터 증강(12장), 검증 가능한 보상(26장)</sub>

- **자기 생성 데이터** `Self-Generated Data` 〔신조〕 — 같은 모델이 만든 데이터로 자기를 학습시키는 것. 걸러 내는 단계가 없으면 효과가 없다. <sub>생긴 때: 2023년 이후 쓰인다</sub>
- **모델 붕괴** `Model Collapse` 〔신조〕 — 모델이 만든 데이터로 반복해 학습하면 다양성이 줄고 품질이 떨어지는 현상. 조건과 정도에 대해 결과가 엇갈린다. <sub>생긴 때: 2023년 이후 논의된다</sub>
- **합성 데이터 걸러내기** `Synthetic Data Filtering` — 만든 데이터 중 쓸 만한 것만 남기는 단계. 이것이 합성 데이터의 성패를 정한다.
- **검증 가능한 과제** `Verifiable Task` — 답이 맞는지 기계로 확인할 수 있는 과제. 합성 데이터가 잘 통하는 자리다.
- **데이터 증폭** `Data Amplification` — 적은 사람 데이터를 씨앗으로 많은 데이터를 만들어 내는 것. 씨앗의 품질이 전체를 정한다.
- **교사 모델 활용** `Teacher Model Use` — 큰 모델로 데이터를 만들어 작은 모델을 가르치는 것. 28장의 증류와 같은 구조이고 약관 확인이 필요하다.
- **데이터 출처 표시** `Synthetic Data Labeling` 〔신조〕 — 사람이 만든 것과 모델이 만든 것을 구별해 기록하는 일. 나중에 문제를 되짚으려면 필요하다. <sub>생긴 때: 2024년 이후 관행으로 자리 잡는 중이다</sub>

### 어느 층을 고칠까

**개선의 다섯 층과 비용**

| 층 | 무엇을 고치나 | 주기 | 되돌리기 |

|---|---|---|---|

| 프롬프트 | 지시와 예시 | 시간 단위 | 즉시 |

| 검색 자료 | 문서와 청킹 | 하루 단위 | 쉽다 |

| 도구 | 설명과 반환 형식 | 하루 단위 | 쉽다 |

| 설정 | 모델 선택과 온도 | 즉시 | 즉시 |

| 가중치 | 미세조정과 재학습 | 주 단위 | 모델 교체 |

위에서부터 시도하는 것이 순서다.
대부분의 개선이 위의 네 층에서 나온다.
가중치를 고치는 것은 위의 것들로 안 될 때의 마지막 수단이고,
모델 세대가 바뀌면 다시 해야 한다는 비용을 같이 세야 한다.

- **프롬프트 개선** `Prompt Iteration` — 실패 사례를 보고 프롬프트를 고치는 것. 가장 싸고 빠른 개선이다.
- **검색 보강** `Retrieval Improvement` — 못 찾은 자료를 채우거나 청킹을 고치는 것. 33장에서 실패를 나눈 결과가 여기로 온다.
- **도구 개선** `Tool Improvement` — 도구 설명과 오류 메시지를 고치는 것. 36장에서 말한 대로 효과가 크다.
- **미세조정 (플라이휠)** `Fine-tuning Loop` — 모아진 데이터로 모델을 고치는 것. 28장의 방법을 쓰고 주기가 길다.
- **재학습** `Retraining` — 정해진 주기로 다시 학습시키는 것. 16장의 분포 이동에 대응하는 방법이다.
- **지속 학습** `Continual Learning` 〔유동〕 — 계속 들어오는 데이터로 이어서 학습시키는 것. 26장의 파국적 망각 때문에 어렵고, 실제로는 주기적 재학습이 흔하다.
- **데이터셋 버전** `Dataset Version` — 어느 시점의 데이터로 학습했는지 기록하는 것. 12장의 데이터 버전 관리다.
- **점진 반영** `Incremental Update` — 한 번에 다 바꾸지 않고 조금씩 반영하는 것. 문제가 생겼을 때 원인을 찾기 쉽다.

### 좋아졌는지 확인하기

- **개선 측정** `Improvement Measurement` — 고친 뒤에 실제로 좋아졌는지 재는 일. <sub>관련어 회귀 평가(42장), A/B 테스트(42장), 범주 나누기(42장)</sub>
- **개선 폭** `Delta` — 바꾸기 전과 후의 차이. 10장의 불확실성 구간을 같이 봐야 우연과 구별된다.
- **부작용 확인** `Side Effect Check` — 고친 것 말고 다른 곳이 나빠졌는지 보는 일. 이것을 빠뜨려서 나는 사고가 흔하다.
- **되돌리기 (개선)** `Rollback` — 나빠졌으면 이전 상태로 돌리는 것. 되돌릴 준비가 되어 있어야 과감하게 시도할 수 있다.
- **개선 기록** `Change Log` — 무엇을 왜 바꿨고 결과가 어땠는지 남기는 것. 없으면 같은 시도를 반복한다.
- **장기 추세** `Long-Term Trend` — 여러 달에 걸친 품질 변화. 한 번의 개선보다 이 곡선이 실제 상태를 말한다.
- **개선 정체** `Plateau` — 더 고쳐도 안 좋아지는 구간. 손대는 층을 바꿔야 한다는 신호다.

### 데이터를 쓸 권리

- **학습 데이터 동의** `Training Data Consent` — 사용자 데이터를 모델 학습에 써도 되는지에 대한 허락. <sub>관련어 동의 확인, 옵트아웃(48장에서 다룬다), 데이터 처리 계약(48장에서 다룬다)</sub>
- **옵트인** `Opt-in` — 동의한 경우에만 쓰는 방식. 데이터가 적게 모이고 문제가 안 생긴다.
- **옵트아웃** `Opt-out` — 기본으로 쓰고 원하면 빼 주는 방식. 데이터가 많이 모이고 논란이 따른다.
- **용도 제한** `Purpose Limitation` — 모은 목적 외에는 쓰지 않는 원칙. 운영을 위해 모은 기록을 학습에 쓰는 것이 여기 걸린다.
- **데이터 삭제 요청** `Deletion Request` — 사용자가 자기 데이터를 지워 달라고 하는 것. 이미 학습에 들어간 경우 되돌리기가 사실상 어렵다.
- **기업 데이터 분리** `Enterprise Data Isolation` — 고객사 데이터를 학습에 안 쓰고 서로 섞이지 않게 하는 것. 기업 계약의 기본 조건이다.
- **데이터 보존 정책** `Retention Policy` — 무엇을 얼마나 오래 둘지 정한 규칙. 43장의 기록과 이 장의 데이터가 같은 정책 아래 있다.

## 자주 헷갈리는 짝

- **플라이휠과 지속 학습** 같은 점은 둘 다 계속 좋아지는 것을 말한다는 것.
다른 점은 층이다. 앞은 절차 전체이고 뒤는 가중치를 고치는 방법이다.
- **합성 데이터와 데이터 증강** 같은 점은 둘 다 데이터를 늘린다는 것.
다른 점은 만드는 방법이다. 모델이 만드는가 변형하는가.
- **명시 피드백과 암묵 신호** 같은 점은 둘 다 품질 신호라는 것.
다른 점은 양과 해석이다. 뒤쪽이 훨씬 많고 해석이 필요하다.
- **평가 집합과 학습 데이터** 같은 점은 둘 다 모은 사례라는 것.
다른 점은 용도다. 섞이면 42장의 오염이 된다.
- **재학습과 미세조정** 같은 점은 둘 다 가중치를 고친다는 것.
다른 점은 규모와 출발점이다.

## 지금 움직이는 것

개선의 무게중심이 가중치에서 그 바깥으로 옮겨 갔다. 모델을 다시 학습시키는 대신 프롬프트와 검색 자료와 도구를 고치는 쪽이 훨씬 빠르고 싸다는 것이 확인되면서다. 동시에 합성 데이터의 비중이 커졌고, 사람이 만든 것과 모델이 만든 것을 구별해 기록하는 관행이 자리 잡는 중이다. 이것으로 8부가 끝난다.
