# 27장 추론과 디코딩

<sub>5부 언어 모델의 해부 · 표제어 45개 · 도해 4개</sub>

> **여는 지도** — 이 장의 낱말 마흔다섯. 모델이 토큰 하나를 내놓기까지 다섯 자리

이 장은 학습이 끝난 모델에서 실제로 글자를 뽑아내는 절차를 다룬다. 26장까지가 모델을 만드는 이야기였다면 여기서부터는 쓰는 이야기다.

모델이 한 번에 내놓는 것은 문장이 아니라 다음 토큰의 확률분포다. 어휘가 10만 개면 10만 개짜리 벡터 하나가 나온다. 그중 하나를 골라야 하고, 고르는 방법이 여러 가지다. 같은 모델이라도 이 방법에 따라 완전히 다르게 답한다.

이 장의 손잡이들이 실무에서 가장 자주 만지는 것들이다. 온도를 얼마로 둘지, 형식을 어떻게 강제할지, 언제 멈출지. 그리고 왜 같은 질문에 매번 다른 답이 나오는지가 여기서 설명된다.

## 표제어

### 모델이 내놓는 것

#### 추론 〔유동〕

<sub>Inference</sub>

**학습이 끝난 모델을 실제로 돌려 출력을 얻는 일.**

갈리는 자리 — 모델을 돌리는 일과 논리적 추론이 한국어로 같은 낱말이다

<sub>관련어 순전파(17장), 디코딩, 추론 능력(30장에서 다룬다), 서빙(41장에서 다룬다)</sub>

- **로짓** `Logit` — 소프트맥스를 지나기 전의 날 점수. 어휘 개수만큼 나온다. <sub>관련어 소프트맥스(17장), 온도, 로짓 편향, 언임베딩(23장)</sub>
- **어휘 분포** `Vocabulary Distribution` — 어휘의 모든 토큰에 확률이 매겨진 상태. 여기서 하나를 뽑는 것이 디코딩이다.
- **디코딩** `Decoding` — 확률분포에서 실제 토큰을 골라 이어 붙이는 절차 전체. 21장의 디코더와 이름이 겹치지만 여기서는 고르는 절차를 가리킨다.
- **생성** `Generation` — 모델이 토큰을 이어 붙여 텍스트를 만드는 일. 디코딩과 거의 같은 뜻으로 쓰인다.

### 분포를 손보는 손잡이

#### 온도

<sub>Temperature</sub>

**로짓을 나누는 값. 확률분포를 뾰족하게 만들거나 평평하게 만든다.**

<sub>관련어 탑피, 탐욕 디코딩, 소프트맥스(17장), 가이던스(21장)</sub>

- **로짓 편향** `Logit Bias` — 특정 토큰의 로짓에 값을 더하거나 빼서 나올 확률을 조절하는 설정. 특정 낱말을 막거나 밀어 줄 때 쓴다.
- **반복 벌점** `Repetition Penalty` — 이미 나온 토큰의 확률을 깎아 같은 말을 되풀이하지 않게 하는 설정. 세게 걸면 필요한 반복까지 막아 문장이 어색해진다.
- **빈도 벌점** `Frequency Penalty` — 많이 나온 토큰일수록 더 크게 깎는 방식. 나온 횟수에 비례한다.
- **존재 벌점** `Presence Penalty` — 한 번이라도 나왔으면 일정하게 깎는 방식. 새 주제로 옮겨 가게 유도한다.
- **금지 토큰** `Banned Tokens` — 절대 나오면 안 되는 토큰의 로짓을 아주 작은 값으로 만들어 막는 것.
- **반복 루프** `Degeneration` — 같은 구절을 끝없이 반복하는 상태. 확률이 높은 것만 고르는 방식에서 자주 생긴다.

### 하나를 고르는 방법

**고르는 방법 여섯**

| 방법 | 어떻게 고르나 | 쓰이는 자리 | 재현성 |

|---|---|---|---|

| 탐욕 | 가장 확률 높은 것 | 형식, 추출 | 높다 |

| 표집 | 확률에 따라 뽑는다 | 대화, 창작 | 낮다 |

| 탑케이 | 상위 k개 중에서 뽑는다 | 일반 대화 | 낮다 |

| 탑피 | 누적 확률 p까지 중에서 | 지금 기본값 | 낮다 |

| 최소 확률 | 최고 확률의 일정 비율 이상 | 최근 방식 | 낮다 |

| 빔 서치 | 후보 여러 줄기를 이어 감 | 번역, 요약 | 높다 |

실제로는 온도와 탑피를 같이 쓴다. 온도로 분포 모양을 정하고
탑피로 꼬리를 자른다. 값을 두 개 다 만지면 상호작용이 있어서,
한 번에 하나씩 바꿔 보는 편이 낫다.

- **탐욕 디코딩** `Greedy Decoding` — 매 단계에서 확률이 가장 높은 토큰 하나를 고르는 방식. <sub>관련어 온도, 표집, 빔 서치(20장), 탐욕법(6장)</sub>
- **표집 (디코딩)** `Sampling` — 확률분포에 따라 무작위로 토큰을 뽑는 방식. <sub>관련어 탑케이, 탑피, 온도, 표집(10장)</sub>
- **탑케이** `Top-k` — 확률이 높은 상위 k개만 남기고 그 안에서 뽑는 방식. 분포가 뾰족하든 평평하든 개수가 고정이라는 것이 약점이다.
- **탑피** `Top-p` — 확률이 높은 것부터 더해 누적이 p에 이를 때까지만 남기고 뽑는 방식. <sub>관련어 탑케이, 온도, 표집, 최소 확률</sub>
- **최소 확률** `Min-p` 〔신조〕 — 가장 높은 확률의 일정 비율보다 낮은 것을 전부 잘라 내는 방식. 분포가 뾰족할 때 후보를 더 잘 좁힌다는 이유로 쓰인다. <sub>생긴 때: 2023년 무렵 제안되었다</sub>
- **전형 표집** `Typical Sampling` — 확률이 너무 높지도 낮지도 않은 토큰을 고르는 방식. 사람이 쓴 글의 정보량 분포에 맞추려는 시도다.
- **시드 고정 (생성)** `Seed` — 무작위 뽑기의 출발값을 고정해 같은 결과를 얻으려는 설정. 서버 쪽 배치 구성 때문에 완전히 같지 않을 수 있다.
- **결정성** `Determinism` 〔유동〕 — 같은 입력에 같은 출력이 나오는 성질. 온도를 0으로 두어도 부동소수점 계산 순서 때문에 완전히 보장되지 않는 경우가 있다.

### 원하는 모양으로 받기

#### 구조화 출력

<sub>Structured Output</sub>

**모델의 답을 정해진 형식으로 받는 것. 대개 JSON 같은 기계가 읽는 형식이다.**

갈리는 자리 — 형식을 강제할 때 품질이 떨어지는지에 대한 결과가 엇갈린다

<sub>관련어 제약 디코딩, JSON(4장), 함수 호출(36장에서 다룬다), 스키마(4장)</sub>

- **제약 디코딩** `Constrained Decoding` — 정해진 문법을 벗어나는 토큰을 막아 형식을 보장하는 방식. 유한 상태 기계나 문법으로 다음에 가능한 토큰을 계산한다.
- **문법 강제** `Grammar-Guided Generation` — 문법을 명시해 그것만 나오게 하는 방식. 형식이 복잡할 때 쓴다.
- **JSON 모드** `JSON Mode` — 답을 JSON으로만 내게 하는 설정. 형식은 보장되고 내용의 정확성은 보장되지 않는다.
- **스키마 준수** `Schema Adherence` — 미리 정한 항목과 타입을 지켜 답하는 정도. 형식만 맞고 값이 엉뚱한 경우가 흔하다.
- **부분 파싱** `Partial Parsing` — 스트리밍 중에 아직 끝나지 않은 구조화 출력을 조금씩 해석하는 일. 화면에 먼저 보여 주려면 필요하다.

### 언제 멈출 것인가

- **정지 토큰** `Stop Token` — 모델이 이 토큰을 내면 생성을 끝내는 표시. 22장의 문장 끝 토큰이 대표적이다.
- **정지 문자열** `Stop Sequence` — 이 글자가 나오면 멈추라고 지정한 문자열. 대화 형식을 벗어나 상대 차례까지 만들어 내는 것을 막는 데 쓴다.
- **최대 토큰** `Max Tokens` — 생성할 토큰 수의 상한. 여기 걸리면 문장 중간에서 잘린다. 비용 상한이자 사고 방지 장치다.
- **길이 벌점** `Length Penalty` — 빔 서치에서 긴 후보와 짧은 후보를 공평하게 비교하려고 점수를 보정하는 값.
- **잘림** `Truncation (Output)` — 상한에 걸려 답이 중간에 끊긴 상태. 끝났는지 잘렸는지를 응답의 종료 이유로 구별해야 한다.
- **종료 이유** `Finish Reason` — 생성이 왜 끝났는지 알려 주는 값. 자연스럽게 끝났는지, 상한에 걸렸는지, 도구를 부르려는지를 구별한다.

### 같은 결과를 빠르게 얻기

- **추측 디코딩** `Speculative Decoding` — 작은 모델이 여러 토큰을 미리 만들고 큰 모델이 한 번에 검사해 맞는 데까지 받아들이는 방법. <sub>관련어 메모리 대역폭(2장), 디코드(24장), 서빙(41장에서 다룬다)</sub>
- **초안 모델** `Draft Model` — 추측 디코딩에서 앞서 만들어 보는 작은 모델. 같은 토크나이저를 써야 한다.
- **다중 토큰 예측** `Multi-Token Prediction` 〔신조〕 — 한 번에 여러 토큰을 예측하도록 학습시켜 생성을 빠르게 하려는 방식. <sub>생긴 때: 2024년 무렵 제안되었다</sub>
- **조기 종료 (층)** `Early Exit` — 쉬운 토큰은 층을 다 안 지나고 중간에서 답을 내는 방식. 평균 계산을 줄인다.
- **배치 추론** `Batch Inference` — 여러 요청을 묶어 한 번에 처리하는 일. 41장에서 자세히 다룬다.
- **스트리밍 생성** `Streaming Generation` — 만들어지는 대로 토큰을 내보내는 방식. 4장의 SSE 위에서 도는 경우가 많다.

### 생성 결과를 다루기

- **후처리** `Post-processing` — 모델이 낸 텍스트를 다듬거나 검사하는 단계. 형식 확인과 금칙어 검사가 여기 들어간다.
- **재시도 (생성)** `Retry` — 형식이 틀렸거나 검사에 걸리면 다시 생성하는 일. 비용이 배로 들어서 몇 번까지 할지 정해 둔다.
- **후보 여러 개** `n-best` — 한 요청에 답을 여러 개 만들어 받는 것. 30장의 자기 일관성과 42장의 평가에 쓴다.
- **로그 확률** `Log Probability` — 각 토큰이 뽑힐 확률에 로그를 씌운 값. 모델이 그 답을 얼마나 확신했는지 보는 데 쓴다.
- **시퀀스 점수** `Sequence Score` — 생성된 문장 전체의 로그 확률 합. 길이에 따라 달라져서 그대로 비교하면 짧은 것이 유리하다.
- **자기 확신** `Self-Confidence` 〔유동〕 — 모델이 자기 답을 얼마나 확신하는지. 로그 확률로 재기도 하고 말로 물어보기도 하는데 둘이 잘 안 맞는다. 46장에서 다시 다룬다.
- **생성 다양성** `Output Diversity` — 같은 질문에 나오는 답들이 얼마나 다른지. 온도와 표집 설정이 정한다.

**과제별 디코딩 설정의 대략적인 출발점**

| 과제 | 온도 | 탑피 | 같이 쓰는 것 |

|---|---|---|---|

| 사실 추출, 분류 | 낮게 | 낮게 | 구조화 출력 |

| 코드 생성 | 낮게 | 중간 | 정지 문자열 |

| 요약 | 낮게에서 중간 | 중간 | 최대 토큰 |

| 대화 | 중간 | 높게 | 반복 벌점 |

| 창작 | 높게 | 높게 | 후보 여러 개 |

| 평가용 재현 | 0 또는 고정 시드 | 해당 없음 | 결정성 확인 |

값은 출발점이고 모델마다 적정 범위가 다르다.
바꿀 때는 하나씩 바꾸고 같은 평가 집합으로 비교한다.
설정을 안 적어 두면 나중에 왜 결과가 달라졌는지 못 찾는다.


## 자주 헷갈리는 짝

- **추론 (모델 실행)과 추론 (논리)** 한국어로 같은 낱말이고 뜻이 다르다.
이 장은 앞쪽이고 30장은 뒤쪽이다.
- **온도와 탑피** 같은 점은 둘 다 다양성을 조절한다는 것.
다른 점은 방식이다. 온도는 분포 모양을 바꾸고 탑피는 꼬리를 자른다.
- **탑케이와 탑피** 같은 점은 둘 다 후보를 좁힌다는 것.
다른 점은 기준이다. 개수인가 누적 확률인가.
- **로짓과 확률** 같은 점은 둘 다 어휘 크기의 벡터라는 것.
다른 점은 소프트맥스를 지났는가다. 손을 대는 것은 대개 로짓 단계다.
- **구조화 출력과 제약 디코딩** 같은 점은 둘 다 형식을 맞추려는 것.
다른 점은 보장 여부다. 제약 디코딩은 형식이 틀릴 수 없다.

## 지금 움직이는 것

디코딩 설정을 사용자에게 덜 노출하는 방향으로 가고 있다. 과제에 맞는 값을 서비스 쪽에서 정하고, 사용자에게는 정확하게와 자유롭게 정도의 단순한 선택만 주는 구성이 늘었다. 동시에 30장의 답하기 전 계산이 늘면서 디코딩 단계 자체가 전체 응답 시간에서 차지하는 비중이 달라지고 있다.

## 더 볼 곳

여기서 나온 속도 이야기가 41장과 44장으로 이어진다. 형식 강제는 36장의 도구 호출에서 실물로 나오고, 여러 답을 만들어 고르는 방식은 30장에서 다시 나온다.
