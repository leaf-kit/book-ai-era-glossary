# 6장 프로그래밍 언어와 자료구조

<sub>1부 컴퓨터라는 바닥 · 표제어 56개 · 도해 3개</sub>

> **여는 지도** — 이 장의 낱말 쉰여섯. 사람이 적은 것이 기계가 도는 것이 되기까지

이 장은 사람이 적은 글자가 어떻게 기계의 명령이 되는지, 그리고 그 사이에 놓인 그릇과 셈법의 이름들을 다룬다.

2장이 명령을 수행하는 회로였고 3장이 그 명령을 나눠 쓰는 규칙이었다면, 여기는 그 명령을 사람이 어떻게 적는가다. 1장의 비트가 여기서 타입이라는 이름을 얻고, 2장의 메모리 계층이 여기서 자료구조를 고르는 이유가 된다.

39장에서 이 장이 통째로 돌아온다. 코딩 에이전트가 무엇을 고치는지 이해하려면 그 코드가 어떤 언어이고 어떤 모양인지가 배경으로 있어야 한다. 빅오 표기는 4부와 5부에서 계속 나온다. 어텐션이 길이의 제곱이라는 말이 무슨 뜻인지가 여기서 정해진다.

|---|---|---|

## 표제어

### 코드가 도는 방식

#### 컴파일

<sub>Compilation</sub>

**사람이 적은 코드를 미리 기계 명령으로 바꿔 두는 일.**

<sub>관련어 인터프리터, 바이트코드, JIT, 링크, 명령어 집합(2장)</sub>

- **인터프리터** `Interpreter` — 코드를 미리 번역하지 않고 한 줄씩 읽으며 바로 수행하는 방식. <sub>관련어 컴파일, 바이트코드, JIT, 런타임</sub>
- **바이트코드** `Bytecode` — 사람이 적은 코드와 기계 명령 사이에 놓인 중간 형태. 한 번 번역해 두고 여러 기계에서 돌릴 수 있다.
- **JIT** `Just-In-Time Compilation` — 돌리는 도중에 자주 쓰이는 부분만 기계 명령으로 번역하는 방식. 실제로 어떻게 쓰이는지를 보고 최적화한다.
- **런타임** `Runtime` 〔유동〕 — 프로그램이 도는 동안 필요한 바탕 환경. 도는 중이라는 시점을 뜻하기도 해서 문맥에 따라 갈린다.
- **링크** `Linking` — 여러 조각으로 번역된 코드를 하나로 잇는 일. 미리 이으면 정적, 돌 때 이으면 동적이다.
- **라이브러리** `Library` — 남이 만들어 둔 코드 묶음. 부르는 쪽이 흐름을 쥐고 있다.
- **프레임워크** `Framework` — 흐름을 쥐고 있고 사이사이를 채우게 하는 코드 묶음. 라이브러리와 반대 방향이다.
- **SDK** `Software Development Kit` — 어떤 서비스를 쓰기 편하게 묶어 놓은 도구와 라이브러리 모음.
- **API** `Application Programming Interface` — 다른 코드가 이쪽 기능을 쓸 수 있게 정해 놓은 창구. 함수 목록일 수도 있고 4장의 HTTP 창구일 수도 있다.

### 값과 타입

#### 타입

<sub>Type</sub>

**어떤 값이 무엇이고 그 값으로 무엇을 할 수 있는지 정한 분류.**

<sub>관련어 정적 타입, 동적 타입, 널, 타입 추론, 스키마(4장)</sub>

- **정적 타입** `Static Typing` — 돌리기 전에 타입을 검사하는 방식. 오류를 일찍 잡고 코드가 길어진다.
- **동적 타입** `Dynamic Typing` — 돌면서 타입을 검사하는 방식. 빨리 적고, 문제가 실제로 그 줄을 지날 때 터진다.
- **타입 추론** `Type Inference` — 적지 않아도 컴파일러가 타입을 알아내는 기능. 정적 타입의 번거로움을 줄인다.
- **널** `Null` — 값이 없음을 나타내는 특별한 값. <sub>관련어 타입, 옵셔널, 예외</sub>
- **옵셔널** `Optional` — 값이 있을 수도 없을 수도 있음을 타입으로 표시한 것. 꺼내기 전에 확인하게 만든다.
- **참조** `Reference` — 값 자체가 아니라 값이 있는 자리를 가리키는 것. <sub>관련어 값 복사, 포인터, 불변, 가비지 컬렉션</sub>
- **포인터** `Pointer` — 메모리 주소를 직접 담는 값. 강력하고 잘못 쓰면 엉뚱한 자리를 건드린다.
- **값 복사** `Copy by Value` — 넘길 때 내용을 통째로 복사하는 방식. 안전하고 크면 비싸다.
- **불변** `Immutable` — 한 번 만들면 안 바뀌는 성질. 여럿이 같이 봐도 안전해서 동시성 문제를 줄인다.
- **가비지 컬렉션** `Garbage Collection, GC` — 더 이상 쓰이지 않는 메모리를 자동으로 찾아 돌려주는 장치. <sub>관련어 메모리 누수(3장), 참조, 수동 메모리 관리</sub>
- **수동 메모리 관리** `Manual Memory Management` — 메모리를 사람이 직접 얻고 돌려주는 방식. 빠르고 예측 가능하며 실수가 잦다.
- **소유권** `Ownership` — 어느 값을 누가 책임지고 정리할지를 컴파일러가 검사하는 방식. 가비지 컬렉션 없이 안전을 얻으려는 시도다.

### 담는 그릇

**자주 쓰는 그릇 여덟과 그 성질**

| 그릇 | 무엇인가 | 빠른 일 | 느린 일 |

|---|---|---|---|

| 배열 | 같은 크기 값이 이어 붙어 있는 것 | 번호로 꺼내기 | 중간에 끼우기 |

| 연결 리스트 | 각 칸이 다음 칸을 가리키는 것 | 끼우고 빼기 | 번호로 꺼내기 |

| 해시맵 | 열쇠로 값을 찾는 표 | 열쇠로 꺼내기 | 순서대로 보기 |

| 집합 | 중복 없는 모음 | 있는지 확인 | 순서 유지 |

| 스택 | 마지막에 넣은 것을 먼저 꺼냄 | 넣고 빼기 | 중간 접근 |

| 큐 | 먼저 넣은 것을 먼저 꺼냄 | 넣고 빼기 | 중간 접근 |

| 트리 | 부모와 자식으로 갈라지는 구조 | 정렬 상태 유지 | 균형 안 맞으면 느려짐 |

| 그래프 | 점과 선으로 이어진 구조 | 관계 따라가기 | 전체 훑기 |

고를 때 보는 것은 무엇을 자주 하느냐다.
그리고 2장의 캐시 때문에, 이론상 느린 배열이 실제로는 연결 리스트보다 빠른 경우가 흔하다.
값이 붙어 있어서 캐시가 잘 맞기 때문이다.

- **배열** `Array` — 같은 종류의 값이 메모리에 이어 붙어 있는 그릇. <sub>관련어 리스트, 텐서(11장에서 다룬다), 지역성(2장)</sub>
- **리스트** `List` 〔유동〕 — 순서가 있는 모음. 언어에 따라 배열을 가리키기도 하고 연결 리스트를 가리키기도 한다.
- **해시맵** `Hash Map` — 열쇠를 해시해서 자리를 정하고 그 자리에 값을 담는 그릇. <sub>관련어 해시(1장), 집합, 충돌(1장)</sub>
- **집합** `Set` — 중복 없는 모음. 있는지 확인하는 일이 빠르다.
- **스택** `Stack` — 마지막에 넣은 것을 먼저 꺼내는 그릇. 함수 호출 기록도 이 구조라 같은 이름으로 부른다.
- **큐** `Queue` — 먼저 넣은 것을 먼저 꺼내는 그릇. 8부의 요청 대기열이 이 구조다.
- **트리** `Tree` — 부모에서 자식으로 갈라지는 구조. 순환이 없다. 5장의 인덱스와 파일 시스템이 이 모양이다.
- **그래프** `Graph` — 점과 선으로 이어진 구조. 순환이 있어도 된다. 37장의 작업 흐름이 이 모양으로 표현된다.
- **힙** `Heap` 〔유동〕 — 가장 큰 값이나 가장 작은 값을 언제나 맨 위에 두어 빨리 꺼내게 만든 트리 구조. 동적으로 얻는 메모리 영역을 뜻하기도 해서 문맥에 따라 갈린다.

### 얼마나 오래 걸리나

#### 빅오 표기

<sub>Big-O Notation</sub>

**입력이 커질 때 걸리는 시간이나 쓰는 공간이 어떻게 늘어나는지 적는 표기.**

<sub>관련어 시간 복잡도, 공간 복잡도, 어텐션(23장에서 다룬다)</sub>

- **시간 복잡도** `Time Complexity` — 입력이 커질 때 걸리는 시간이 늘어나는 모양.
- **공간 복잡도** `Space Complexity` — 입력이 커질 때 쓰는 메모리가 늘어나는 모양. 24장의 KV 캐시가 문제가 되는 것이 이 축이다.
- **상수 시간** `Constant Time` — 입력이 커져도 걸리는 시간이 그대로인 성질. 배열에서 번호로 꺼내는 일이 그렇다.
- **선형** `Linear` — 입력에 비례해 늘어나는 성질. 목록을 한 번 훑는 일이 그렇다.
- **정렬 (자료구조)** `Sorting` — 순서대로 늘어놓는 일. 잘 만든 방법이 대략 n 곱하기 로그 n 만큼 걸린다. 26장의 정렬과 다른 낱말이다.
- **이진 탐색** `Binary Search` — 정렬된 것에서 절반씩 줄여 가며 찾는 방법. 백만 개에서 스무 번이면 찾는다.
- **동적 계획법** `Dynamic Programming` — 작은 문제의 답을 적어 두고 다시 쓰는 방식. 같은 계산을 반복하지 않게 만든다.
- **탐욕법** `Greedy` — 매 순간 가장 좋아 보이는 것을 고르는 방식. 빠르고 최선이 아닐 수 있다. 27장의 디코딩에서 같은 이름이 나온다.

### 코드를 짜는 방식

- **객체지향** `Object-Oriented Programming, OOP` — 데이터와 그 데이터를 다루는 함수를 하나로 묶어 다루는 방식. <sub>관련어 캡슐화, 상속, 다형성, 인터페이스</sub>
- **캡슐화** `Encapsulation` — 안쪽 데이터를 감추고 정해진 창구로만 다루게 하는 것.
- **상속** `Inheritance` — 기존 것의 성질을 물려받아 새것을 만드는 방식. 깊어지면 흐름을 따라가기 어렵다.
- **다형성** `Polymorphism` — 같은 이름으로 불러도 대상이 무엇이냐에 따라 다르게 동작하는 성질. 여러 모양을 가진다는 뜻의 이름이다.
- **인터페이스** `Interface` — 무엇을 할 수 있는지만 정하고 어떻게 하는지는 안 정한 약속. 0장의 명세와 같은 발상이다.
- **함수형** `Functional Programming` — 상태를 바꾸지 않고 값을 받아 값을 돌려주는 함수로 짜는 방식. <sub>관련어 순수 함수, 부작용, 불변, 재귀</sub>
- **순수 함수** `Pure Function` — 같은 입력에 늘 같은 출력을 내고 바깥을 안 건드리는 함수.
- **부작용** `Side Effect` — 함수가 값을 돌려주는 것 말고 바깥에 남기는 변화. 36장에서 도구 호출의 부작용이 중요한 문제가 된다.
- **재귀** `Recursion` — 함수가 자기 자신을 부르는 방식. 트리처럼 자기 닮은 구조에 잘 맞고, 깊어지면 스택이 넘친다.
- **예외** `Exception` — 정상 흐름으로 처리할 수 없는 상황을 알리고 위로 던지는 장치. <sub>관련어 오류 처리, 스택 트레이스, 널</sub>
- **스택 트레이스** `Stack Trace` — 오류가 났을 때 어느 함수를 거쳐 왔는지 적힌 기록. 43장에서 다시 나온다.
- **어서션** `Assertion` — 여기서는 반드시 이래야 한다고 적어 두고 아니면 멈추게 하는 검사.
- **리팩터링** `Refactoring` — 동작을 바꾸지 않고 코드의 모양만 고치는 일. 시험이 있어야 안전하게 할 수 있다.
- **기술 부채** `Technical Debt` 〔유동〕 — 지금 빨리 가려고 미뤄 둔 정리. 미룰수록 나중에 더 든다는 비유이고, 무엇까지 부채로 부를지가 사람마다 다르다.
- **의사코드** `Pseudocode` — 특정 언어 문법을 안 쓰고 절차만 적은 코드. 이 책의 코드가 대부분 이 형태다.

## 자주 헷갈리는 짝

- **컴파일과 인터프리터** 같은 점은 둘 다 코드를 명령으로 바꾼다는 것.
다른 점은 언제 바꾸는가다. 미리인가 그때그때인가.
- **라이브러리와 프레임워크** 같은 점은 둘 다 남이 만든 코드라는 것.
다른 점은 누가 흐름을 쥐는가다. 내가 부르면 라이브러리, 나를 부르면 프레임워크다.
- **배열과 연결 리스트** 같은 점은 둘 다 순서가 있는 모음이라는 것.
다른 점은 붙어 있는가다. 붙어 있으면 번호 접근이 빠르고 캐시가 잘 맞는다.
- **힙 (자료구조)과 힙 (메모리)** 같은 글자이고 뜻이 다르다.
앞은 우선순위 큐를 만드는 트리이고 뒤는 동적으로 얻는 메모리 영역이다.
- **파라미터와 아규먼트** 같은 점은 둘 다 함수에 넘기는 값을 가리킨다는 것.
다른 점은 선언 쪽인가 호출 쪽인가다. 4부의 학습 파라미터와는 완전히 다른 낱말이다.

## 지금 움직이는 것

타입을 덧붙이는 흐름이 굳었다. 동적 언어들이 타입 표기를 받아들이고, 그 표기를 도구가 검사하는 방식이 널리 자리 잡았다. 코드 생성 도구가 늘면서 이 흐름이 더 강해졌다. 사람이 안 읽는 코드가 늘수록 기계가 검사할 수 있는 표기의 값이 올라간다.

## 더 볼 곳

여기서 나온 빌드와 라이브러리가 7장으로 이어진다. 빅오 표기는 24장에서 문맥 길이 비용으로 돌아오고, 자료구조는 34장의 벡터 인덱스에서 다시 나온다.
