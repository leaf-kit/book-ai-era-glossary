# 2장 프로세서와 메모리

<sub>1부 컴퓨터라는 바닥 · 표제어 40개 · 도해 4개</sub>

> **여는 지도** — 이 장의 낱말 마흔. 아래로 갈수록 크고 느리고, 위로 갈수록 작고 빠르다

이 장은 1장의 비트가 실제로 어디에 놓이고 어떻게 움직이는지를 다룬다. 계산은 빠르고 데이터를 옮기는 일은 느리다. 이 한 문장이 이 장의 전부다.

프로세서 안에서 덧셈 하나는 1나노초도 안 걸린다. 그 숫자를 주기억 장치에서 가져오는 데는 100나노초쯤 걸린다. 백 배 차이다. 그래서 컴퓨터 구조의 역사는 계산을 빠르게 만드는 역사가 아니라 데이터를 가까이 두는 역사에 가깝다. 캐시가 있는 이유가 이것이고, 층이 여러 개인 이유도 이것이다.

이 장이 5부와 8부에서 계속 돌아온다. 모델을 돌릴 때 병목이 계산이 아니라 대역폭인 경우가 많고, KV 캐시 (이미 계산한 키와 값을 들고 있다가 다시 쓰는 저장, 24장)의 캐시가 여기서 온 낱말이며, 배치 크기를 키우면 왜 처리량이 오르는지도 여기서 설명된다. 1장의 부동소수점 형식이 왜 그렇게 여러 개인지도 결국 대역폭 문제다.

## 한눈에 보기

| 무리 | 무엇을 다루나 | 어디서 다시 쓰나 |
|---|---|---|
| 계산하는 부분 | 명령을 실제로 수행하는 회로 | 6장, 50장 |
| 빠르게 만드는 장치 | 기다리지 않게 만드는 요령 | 41장, 44장 |
| 기억 계층 | 크기와 속도를 맞바꾸는 층들 | 24장 KV 캐시, 44장 |
| 가속기 | 같은 계산을 한꺼번에 하는 칩 | 4부 전체, 50장 |


## 표제어

### 계산하는 부분

#### CPU

<sub>Central Processing Unit</sub>

**명령을 하나씩 읽어서 순서대로 수행하는 중앙 처리 장치.**

<sub>관련어 코어, 클럭, 명령어 집합, 파이프라인, GPU</sub>

- **코어** `Core` — 프로세서 안에서 명령을 독립적으로 수행할 수 있는 한 벌. <sub>관련어 스레드, 동시성(3장에서 다룬다), 하이퍼스레딩</sub>
- **하이퍼스레딩** `Hyper-Threading, SMT` — 코어 하나를 둘처럼 보이게 하는 기술. 한 스레드가 메모리를 기다리는 동안 다른 스레드가 회로를 쓴다. 코어가 진짜로 늘어난 것은 아니다.
- **레지스터** `Register` — 프로세서 안에 있는 가장 빠른 저장 자리. 몇십 개뿐이고 크기가 워드 하나다. 계산 중인 값이 여기 있다.
- **ALU** `Arithmetic Logic Unit` — 더하기와 비교 같은 기본 연산을 하는 회로. 산술 논리 장치라고 옮긴다. 프로세서 안에서 실제로 계산을 맡는 자리다.
- **명령어 집합** `Instruction Set Architecture, ISA` — 프로세서가 알아듣는 명령의 목록과 그 형식. <sub>관련어 CPU, 컴파일(6장에서 다룬다), 가상화(8장에서 다룬다)</sub>
- **클럭** `Clock` — 프로세서 안의 모든 동작을 맞추는 박자. 초당 몇 번인지를 헤르츠로 적는다. <sub>관련어 IPC, 코어, 전력(50장에서 다룬다)</sub>
- **IPC** `Instructions Per Cycle` — 한 박자에 끝내는 명령의 개수. 클럭이 같아도 이 값이 다르면 성능이 다르다. 8부의 초당 요청 수와 다른 낱말이다.

### 기다리지 않게 만드는 장치

#### 파이프라인

<sub>Pipeline</sub>

**한 명령을 여러 단계로 쪼개고, 단계마다 다른 명령을 동시에 처리하는 방식.**

<sub>관련어 분기 예측, 비순차 실행, 파이프라인 병렬(50장에서 다룬다)</sub>

- **분기 예측** `Branch Prediction` — 조건문에서 어느 쪽으로 갈지 미리 찍는 장치. <sub>관련어 파이프라인, 비순차 실행</sub>
- **비순차 실행** `Out-of-Order Execution` — 앞의 명령이 값을 기다리는 동안 뒤의 명령을 먼저 실행하는 방식. 결과는 원래 순서대로 반영한다.
- **추측 실행** `Speculative Execution` — 결과를 확정하기 전에 미리 실행해 두는 방식. 성능은 오르지만 이 방식을 이용한 보안 취약점이 알려져 있다.
- **SIMD** `Single Instruction, Multiple Data` — 명령 하나로 여러 데이터에 같은 계산을 한꺼번에 하는 방식. <sub>관련어 GPU, 벡터화, 텐서 코어</sub>
- **벡터화** `Vectorization` — 반복문을 SIMD 명령으로 바꾸는 일. 컴파일러가 자동으로 하기도 하고 사람이 직접 적기도 한다.

### 기억의 계층

#### 메모리 계층

<sub>Memory Hierarchy</sub>

**빠르고 작은 저장과 느리고 큰 저장을 여러 층으로 쌓아 둔 구조.**

<sub>관련어 캐시, DRAM, 지역성, 메모리 대역폭</sub>

- **캐시** `Cache` — 느린 곳에서 가져온 것을 가까운 곳에 잠깐 두고 다시 쓰는 장치. <sub>관련어 캐시 라인, 캐시 미스, 지역성, 프롬프트 캐시(44장에서 다룬다)</sub>
- **캐시 라인** `Cache Line` — 캐시가 한 번에 가져오는 덩어리. 대개 64바이트다. 1바이트만 필요해도 64바이트를 가져온다.
- **캐시 미스** `Cache Miss` — 찾는 값이 캐시에 없어서 아래 층까지 내려가야 하는 일. 미스 한 번이 수백 박자를 잡아먹는다.
- **지역성** `Locality` — 방금 쓴 것을 곧 다시 쓰고, 옆에 있는 것을 이어서 쓰는 성질. 캐시가 도움이 되는 이유 전부가 이것이다.
- **프리페치** `Prefetch` — 곧 필요할 것 같은 데이터를 미리 가져오는 일. 접근 패턴이 규칙적일 때만 잘 맞는다.
- **캐시 무효화** `Cache Invalidation` — 원본이 바뀌었을 때 캐시에 있는 옛 값을 버리는 일. 어렵기로 이름난 문제다.
- **DRAM** `Dynamic Random Access Memory` — 주기억 장치에 쓰는 메모리. 전기가 끊기면 내용이 사라진다. <sub>관련어 메모리 대역폭, HBM, 메모리 계층, 메모리 벽(50장에서 다룬다)</sub>

#### 메모리 대역폭

<sub>Memory Bandwidth</sub>

**초당 주기억 장치와 프로세서 사이를 오갈 수 있는 데이터의 양.**

<sub>관련어 DRAM, HBM, 메모리 계층, 배칭(41장에서 다룬다)</sub>

- **HBM** `High Bandwidth Memory` — 메모리 칩을 여러 층으로 쌓고 넓은 통로로 연결한 방식. 가속기에 붙어 있고 일반 메모리보다 대역폭이 훨씬 넓다.
- **NUMA** `Non-Uniform Memory Access` — 프로세서마다 가까운 메모리와 먼 메모리가 따로 있어서, 어느 쪽을 읽느냐에 따라 걸리는 시간이 달라지는 구조. 먼 쪽을 읽으면 느려져서, 어느 메모리에 데이터를 두는지가 성능을 가른다.
- **메모리 채널** `Memory Channel` — 프로세서와 메모리를 잇는 통로의 개수. 채널이 늘면 대역폭이 는다.

**어디서 읽느냐에 따른 대략적인 거리감**

| 자리 | 걸리는 시간의 대략 | 크기의 대략 |

|---|---|---|

| 레지스터 | 1박자 | 몇백 바이트 |

| L1 캐시 | 몇 박자 | 수십 킬로바이트 |

| L2 캐시 | 십여 박자 | 수백 킬로바이트에서 몇 메가바이트 |

| L3 캐시 | 수십 박자 | 수십 메가바이트 |

| 주기억 장치 | 수백 박자 | 수십에서 수백 기가바이트 |

| 가속기 메모리 | 수백 박자 | 수십에서 수백 기가바이트 |

| SSD | 수만에서 수십만 박자 | 테라바이트 |

| 네트워크 저편 | 그보다 훨씬 | 사실상 무제한 |

정확한 값은 기계마다 다르다. 외울 것은 숫자가 아니라 자릿수 차이다.
한 층 내려갈 때마다 대략 열 배씩 멀어진다.

### 한꺼번에 계산하는 칩

#### GPU

<sub>Graphics Processing Unit</sub>

**같은 계산을 아주 많이 동시에 하도록 만든 프로세서.**

갈리는 자리 — 화면 출력이 있는 칩만 가리키는 자리와 계산 전용 칩까지 포함하는 자리가 섞여 있다

<sub>관련어 가속기, 텐서 코어, CUDA, 메모리 대역폭, SIMD</sub>

- **가속기** `Accelerator` — 특정 계산을 빠르게 하려고 따로 만든 칩. <sub>관련어 GPU, TPU, 텐서 코어, 50장</sub>
- **TPU** `Tensor Processing Unit` — 구글이 만든 기계학습 전용 가속기. 행렬 곱셈에 특화되어 있다. 이름이 널리 쓰이지만 특정 회사의 제품이다.
- **텐서 코어** `Tensor Core` — 작은 행렬 곱셈을 통째로 한 번에 처리하는 회로. 반정밀도 이하 형식에서 특히 빠르다.
- **CUDA** `Compute Unified Device Architecture` — 엔비디아 GPU에 계산을 시키는 개발 환경. 사실상 표준이 되어 있어서 다른 회사 칩으로 옮기기 어려운 원인이 된다.
- **커널 (GPU)** `Kernel` 〔유동〕 — GPU에서 실행되는 함수 하나. 3장의 운영체제 커널, 19장의 합성곱 커널과 이름만 같고 다른 것이다.
- **FLOPS** `Floating Point Operations Per Second` — 초당 부동소수점 연산 횟수. 계산 성능을 적는 단위다. 어느 정밀도 기준인지를 안 적으면 비교가 안 된다.
- **점유율** `Utilization` 〔유동〕 — 가속기가 노는 시간 없이 일하는 비율. 무엇을 세느냐가 회사마다 달라 같은 이름의 값이 다르게 나온다.
- **연산 강도** `Arithmetic Intensity` — 데이터 1바이트를 가져올 때마다 하는 계산의 양. <sub>관련어 메모리 대역폭, FLOPS, 배칭(41장에서 다룬다)</sub>

### 저장 장치

- **SSD** `Solid State Drive` — 반도체에 데이터를 담는 저장 장치. 움직이는 부품이 없어 접근이 빠르다.
- **HDD** `Hard Disk Drive` — 자기 원판을 돌려 데이터를 담는 저장 장치. 느리지만 용량당 값이 싸서 대량 보관에 남아 있다.
- **NVMe** `Non-Volatile Memory Express` — SSD를 프로세서에 직접 붙이는 통로 규격. 옛 규격보다 지연이 훨씬 낮다.
- **지속성** `Persistence` — 전원이 꺼져도 남는 성질. 메모리에는 없고 저장 장치에는 있다. 5장의 트랜잭션 이야기가 이 성질 위에 서 있다.
- **IOPS** `Input/Output Operations Per Second` — 초당 읽기 쓰기 횟수. 저장 장치 성능을 적는 단위이고, 대역폭과 다른 축이다.

## 자주 헷갈리는 짝

- **대역폭과 지연** 같은 점은 둘 다 속도를 나타낸다는 것.
다른 점은 대역폭이 시간당 양이고 지연이 한 번의 기다림이라는 것.
넓은 파이프와 짧은 파이프는 다른 이야기다.
- **캐시와 버퍼** 같은 점은 둘 다 데이터를 잠깐 들고 있다는 것.
다른 점은 캐시가 다시 쓰려고 들고 있고 버퍼는 속도 차이를 메우려고 들고 있다는 것.
- **코어와 스레드** 같은 점은 둘 다 동시에 도는 것을 세는 단위라는 것.
다른 점은 코어가 하드웨어이고 스레드가 소프트웨어라는 것. 3장에서 다시 나온다.
- **CPU와 GPU** 같은 점은 둘 다 명령을 수행한다는 것.
다른 점은 CPU가 갈라지는 일을 잘하고 GPU가 같은 일을 많이 하는 것을 잘한다는 것.
- **FLOPS와 대역폭** 같은 점은 둘 다 칩의 성능 수치라는 것.
다른 점은 앞이 계산 능력이고 뒤가 데이터 공급 능력이라는 것. 대부분의 병목은 뒤쪽이다.

## 지금 움직이는 것

가속기 메모리 용량이 모델 설계를 정하는 상황이 이어지고 있다. 한 장에 안 들어가면 여러 장에 나눠야 하고, 나누면 장 사이 통로가 새 병목이 된다. 그래서 최근 몇 해의 하드웨어 발표는 계산 성능보다 메모리 용량과 상호연결 대역폭을 앞세운다.

## 더 볼 곳

여기서 나온 코어와 스레드가 3장에서 운영체제의 이야기로 이어진다. 대역폭과 배칭은 41장과 44장에서 다시 나오고, 가속기는 50장에서 돈 이야기가 된다.
