# 47장 공격과 방어

<sub>9부 위험과 규범과 지형 · 표제어 55개 · 도해 3개</sub>

> **여는 지도** — 이 장의 낱말 쉰다섯. 아래에서 위로 갈수록 공격이 시스템 깊이 들어간다

이 장은 누가 일부러 무너뜨리는 방식과 막는 방식을 다룬다. 46장이 스스로 실패하는 이야기였다면 여기는 공격이다.

9장의 낱말이 통째로 돌아온다. 위협 모델, 최소 권한, 심층 방어, 주입. 새로 생긴 것은 하나다. 모델에게는 지시와 데이터가 같은 글자로 들어온다. 9장에서 주입을 막는 방법은 데이터와 명령을 갈라 다루는 것이었는데, 여기서는 그 방법이 안 통한다.

그래서 이 장의 결론이 조금 다르다. 모델 층에서 완전히 막을 방법이 지금은 없다. 막는 자리를 밖으로 옮겨야 한다. 무엇을 할 수 있는지 제한하고, 되돌릴 수 없는 일에 사람을 두고, 뚫렸을 때 피해를 줄이는 쪽으로 설계한다.

## 표제어

### 지시를 바꿔 넣는 것

#### 프롬프트 주입

<sub>Prompt Injection</sub>

**입력에 지시처럼 보이는 내용을 넣어 원래 지시를 무시하게 만드는 공격.**

<sub>관련어 간접 주입, 탈옥, 주입(9장), 최소 권한(9장)</sub>

#### 간접 주입 〔신조〕

<sub>Indirect Prompt Injection</sub>

**모델이 읽어 오는 문서나 웹페이지나 도구 결과 안에 지시를 숨겨 놓는 공격.**

생긴 때 — 2023년 이후 이름이 자리 잡았다

<sub>관련어 프롬프트 주입, 신뢰 경계(32장), 도구 결과(36장), 혼동된 대리인(36장)</sub>

- **시스템 프롬프트 유출** `System Prompt Leakage` — 숨겨 둔 지시를 알아내는 것. 대개 큰 피해는 아니지만 그 안에 열쇠나 내부 규칙이 있으면 문제가 된다.
- **역할 우회** `Role Confusion` — 사용자 입력을 시스템 지시처럼 보이게 만들어 우선순위를 뒤집는 것. 형식을 흉내 내는 방식이다.
- **지시 덮어쓰기** `Instruction Override` — 앞의 지시를 무시하라고 적어 넣는 것. 가장 단순한 형태이고 지금은 대개 막힌다.
- **인코딩 우회** `Encoding Evasion` — 다른 언어나 부호로 바꿔 검사를 피하는 것. 1장의 인코딩이 여기서 우회 수단이 된다.
- **다단계 주입** `Multi-Stage Injection` 〔신조〕 — 여러 걸음에 걸쳐 조금씩 상태를 바꿔 놓는 공격. 한 걸음만 보면 이상하지 않다. <sub>생긴 때: 2024년 이후 보고된다</sub>
- **페이로드 은닉** `Hidden Payload` — 사람 눈에 안 보이게 지시를 숨기는 것. 흰 글자, 아주 작은 글자, 이미지 안의 글자가 쓰인다.

### 제약을 우회하는 것

- **탈옥** `Jailbreak` — 모델이 안 하도록 정렬된 일을 하게 만드는 시도. <sub>관련어 프롬프트 주입, 탈옥 저항(26장), 레드팀, 안전 필터</sub>
- **역할극 우회** `Roleplay Jailbreak` — 가상의 인물이나 상황을 설정해 제약을 피하는 방식. 창작 요청과 구별이 어려운 것이 근본 문제다.
- **점진적 유도** `Crescendo` 〔신조〕 — 무해한 질문에서 시작해 조금씩 옮겨 가는 방식. 각 걸음은 정상이라 걸러 내기 어렵다. <sub>생긴 때: 2024년 무렵 이름이 붙었다</sub>
- **다국어 우회** `Multilingual Evasion` — 안전 학습이 덜 된 언어로 요청하는 방식. 언어별 정렬 차이를 이용한다.
- **많은 예시 공격** `Many-Shot Jailbreak` 〔신조〕 — 긴 문맥에 예시를 아주 많이 넣어 앞의 지시를 묻히게 하는 방식. 문맥 창이 길어지면서 생긴 공격이다. <sub>생긴 때: 2024년 무렵 보고되었다</sub>
- **적대적 접미사** `Adversarial Suffix` — 자동으로 찾아낸 무의미해 보이는 문자열을 붙여 제약을 우회하는 방식. 사람이 읽으면 뜻이 없다.
- **자동 탈옥 탐색** `Automated Jailbreak Search` 〔신조〕 — 다른 모델로 우회 문구를 자동으로 찾아내는 방식. 공격 비용을 크게 낮춘다. <sub>생긴 때: 2023년 이후 보고된다</sub>

### 안에 있는 것을 빼내기

- **데이터 유출** `Data Exfiltration` — 시스템 안의 정보를 밖으로 빼내는 것. <sub>관련어 간접 주입, 네트워크 격리(36장), 도구 연쇄 위험(36장), 개인정보(48장에서 다룬다)</sub>
- **학습 데이터 추출** `Training Data Extraction` — 모델이 외운 학습 데이터를 끌어내는 공격. 13장의 암기가 있으면 가능하고, 48장의 권리 문제와 직결된다.
- **멤버십 추론** `Membership Inference` — 특정 데이터가 학습에 쓰였는지 알아내는 공격. 개인정보가 들어갔는지 확인하는 데 쓰인다.
- **모델 추출** `Model Extraction` — 많이 물어보고 그 답으로 비슷한 모델을 만드는 것. 28장의 증류를 허락 없이 하는 셈이다.
- **프롬프트 도용** `Prompt Theft` — 공들여 만든 시스템 프롬프트를 알아내는 것. 서비스의 차별점이 프롬프트에 있으면 손해가 된다.
- **부채널** `Side Channel` — 응답 시간이나 토큰 수 같은 부수적 정보로 내용을 추측하는 공격. 스트리밍에서 길이가 새는 문제가 알려져 있다.
- **숨은 출력** `Hidden Output` — 사람 눈에 안 보이게 답에 정보를 심는 것. 사용자가 그것을 다른 곳에 붙여 넣으면 정보가 옮겨 간다.

### 도구와 권한을 노리기

**에이전트 공격의 다섯 경로**

| 경로 | 어떻게 | 막는 자리 | 남는 위험 |

|---|---|---|---|

| 읽어 온 문서 | 안에 지시를 숨긴다 | 신뢰 경계 표시 | 완전하지 않다 |

| 도구 설명 | 설명에 지시를 심는다 | 서버 출처 확인 | 남의 서버 |

| 명령 실행 | 인자에 명령을 끼운다 | 인자 검증, 샌드박스 | 샌드박스 탈출 |

| 권한 이어 붙이기 | 여러 도구를 엮는다 | 권한 분리 | 조합의 수 |

| 승인 피로 | 확인을 무디게 만든다 | 승인 지점 줄이기 | 사람의 한계 |

마지막 줄이 기술로 안 풀리는 자리다.
확인 요청이 하루에 백 번 오면 사람은 내용을 안 보고 누른다.
그래서 승인을 붙일 자리를 줄이고, 붙인 자리에서는 무엇을 승인하는지 명확히 보여야 한다.

- **권한 상승 (에이전트)** `Privilege Escalation` — 에이전트가 원래 못 하던 일을 하게 되는 것. 도구를 이어 붙여 생기는 경우가 많다.
- **명령 주입** `Command Injection` — 도구 인자에 명령을 끼워 넣는 것. 9장의 주입이 도구 층에서 나타난 형태다.
- **샌드박스 탈출** `Sandbox Escape` — 격리된 환경에서 밖으로 나가는 것. 8장에서 말한 대로 커널을 같이 쓰는 격리는 이 위험이 남는다.
- **도구 설명 오염** `Tool Description Poisoning` 〔신조〕 — 도구 설명에 숨은 지시를 넣어 모델을 조종하는 것. 남이 만든 서버를 붙일 때 생긴다. <sub>생긴 때: 2024년 이후 보고된다</sub>
- **악성 서버** `Malicious Server` 〔신조〕 — 정상적인 척하며 정보를 빼내거나 조종하는 도구 서버. 36장의 규격이 퍼지면서 새로 생긴 위험이다. <sub>생긴 때: 2024년 이후 쓰인다</sub>
- **자동 승인 악용** `Auto-approval Abuse` 〔신조〕 — 자동으로 통과되는 조건을 만족시키도록 요청을 꾸미는 것. 조건이 넓을수록 위험하다. <sub>생긴 때: 2024년 이후 쓰인다</sub>
- **연쇄 권한** `Chained Permissions` 〔신조〕 — 개별로는 안전한 권한들이 합쳐져 위험해지는 것. 읽기와 발신이 대표적인 조합이다. <sub>생긴 때: 2024년 이후 쓰인다</sub>

### 가져다 쓰는 것에 심기

- **데이터 오염 공격** `Data Poisoning` — 학습 데이터에 나쁜 것을 심어 모델의 행동을 바꾸는 공격. <sub>관련어 백도어, 공급망 공격(9장), 데이터 선별(45장), 코퍼스(25장)</sub>
- **백도어** `Backdoor` — 특정 방아쇠에서만 나타나는 숨은 행동. 평소에는 정상이라 발견이 어렵다.
- **모델 공급망** `Model Supply Chain` 〔신조〕 — 모델 파일과 어댑터와 도구 서버를 가져다 쓰는 경로. 7장의 의존성 문제가 이 층에서 반복된다. <sub>생긴 때: 2023년 이후 쓰인다</sub>
- **가중치 변조** `Weight Tampering` — 내려받은 모델 파일이 바뀌어 있는 것. 9장의 서명으로 확인한다.
- **악성 문서** `Malicious Document` 〔신조〕 — 검색이나 열람 대상 안에 공격이 심어진 문서. 간접 주입의 재료다. <sub>생긴 때: 2023년 이후 쓰인다</sub>
- **패키지 사칭** `Typosquatting` — 이름이 비슷한 가짜 꾸러미를 올려 두는 것. 39장에서 에이전트가 의존성을 추가할 때 걸릴 수 있다.
- **환각 패키지** `Slopsquatting` 〔신조〕 — 모델이 자주 지어내는 없는 꾸러미 이름을 공격자가 미리 만들어 두는 것. 39장의 환각이 공격 경로가 된 사례다. <sub>생긴 때: 2024년 무렵 이름이 붙었다</sub>

### 어떻게 막나

#### 심층 방어

<sub>Defense in Depth</sub>

**한 겹이 뚫려도 다음 겹이 막게 여러 층으로 방어하는 설계.**

<sub>관련어 최소 권한(9장), 격리, 출력 검사, 감사 기록(36장)</sub>

- **입력 검사** `Input Filtering` — 들어오는 내용에서 공격 패턴을 찾는 것. 우회가 쉬워 첫 겹 이상은 못 된다.
- **신뢰 경계 표시** `Trust Marking` — 어디까지가 믿을 수 있는 내용인지 문맥에 표시하는 것. 완전하지 않고 안 하는 것보다는 낫다.
- **권한 분리** `Privilege Separation` — 읽는 에이전트와 쓰는 에이전트를 나누는 것. 유출 경로를 끊는 가장 확실한 설계다.
- **이중 확인** `Two-Person Rule` — 중요한 조작에 두 사람의 확인을 요구하는 것. 오래된 방식이고 자동화에도 적용된다.
- **자동 공격 시험** `Automated Adversarial Testing` 〔신조〕 — 공격 문구를 자동으로 만들어 대량으로 시험하는 것. 사람 레드팀을 보완한다. <sub>생긴 때: 2023년 이후 쓰인다</sub>
- **속도 제한 (방어)** `Rate Limiting for Defense` — 같은 사용자가 반복해서 시도하는 것을 제한하는 것. 탐색형 공격의 비용을 올린다.
- **이상 사용 탐지** `Abuse Detection` — 공격으로 보이는 사용 패턴을 찾아내는 것. 43장의 이상 탐지를 보안에 쓴 것이다.
- **사고 대응** `Incident Response` — 뚫렸을 때 무엇을 어떤 순서로 할지 정해 둔 절차. 미리 없으면 그때 만든다.
- **복구 계획** `Recovery Plan` — 피해를 되돌리는 절차. 되돌릴 수 없는 행동이 무엇인지 미리 파악해 두어야 세울 수 있다.

**에이전트를 붙이기 전에 확인할 여덟 가지**

| 항목 | 무엇을 확인하나 |

|---|---|

| 읽을 수 있는 범위 | 어디까지 볼 수 있고 그것이 새면 얼마나 나쁜가 |

| 바꿀 수 있는 범위 | 무엇을 바꿀 수 있고 되돌릴 수 있는가 |

| 나갈 수 있는 통로 | 밖으로 데이터를 보낼 수 있는 경로가 있는가 |

| 신뢰할 수 없는 입력 | 어디에서 바깥 내용이 들어오는가 |

| 승인 지점 | 무엇에 사람 확인이 붙어 있는가 |

| 상한 | 걸음과 비용과 시간의 상한이 있는가 |

| 기록 | 무엇을 했는지 사후에 알 수 있는가 |

| 중단 | 돌고 있는 것을 멈출 수 있는가 |

이 여덟에 답할 수 없으면 아직 붙일 준비가 안 된 것이다.
셋째와 넷째가 같이 있으면 유출 경로가 완성되어 있다는 뜻이고,
그 조합이 가장 자주 놓치는 자리다.

### 위험을 판단하기

- **위협 모델 (에이전트)** `Threat Model` — 무엇을 누구로부터 지킬지 정해 두는 것. <sub>관련어 위협 모델(9장), 공격 표면(9장), 최소 권한(9장), 정책(49장에서 다룬다)</sub>
- **공격 표면 (에이전트)** `Attack Surface` — 바깥에서 건드릴 수 있는 지점의 총합. 도구를 늘릴 때마다 같이 는다.
- **피해 범위** `Blast Radius` — 뚫렸을 때 피해가 미치는 범위. 권한을 좁히면 이 값이 준다.
- **탐지 시간** `Time to Detect` — 공격이 일어나고 알아채기까지의 시간. 기록이 없으면 이 값이 무한이다.
- **책임 경계** `Responsibility Boundary` — 모델 제공자와 서비스 제공자와 사용자 중 누가 무엇을 책임지는지. 8장의 책임 공유 모델이 여기서도 필요하다.
- **안전 사례** `Safety Case` 〔신조〕 — 왜 이 시스템이 충분히 안전한지를 근거와 함께 적은 문서. 49장의 논의에서 요구되기 시작했다. <sub>생긴 때: 2024년 이후 쓰인다</sub>
- **공개 취약점 보고** `Responsible Disclosure` — 취약점을 발견했을 때 고칠 시간을 주고 알리는 관행. 모델 쪽에도 같은 절차가 자리 잡는 중이다.
- **모델 역전** `Model Inversion` — 모델의 출력을 계속 관찰해 학습 데이터에 무엇이 있었는지 되짚는 공격. 48장의 개인정보 문제와 이어진다.
- **속성 추론** `Attribute Inference` — 공개된 정보와 모델의 반응을 합쳐 감춰진 속성을 알아내는 공격. 개별 기록이 안 새도 결과적으로 드러난다.

## 자주 헷갈리는 짝

- **프롬프트 주입과 탈옥** 같은 점은 둘 다 원래 의도와 다르게 동작하게 만든다는 것.
다른 점은 대상이다. 앞은 지시를 바꾸고 뒤는 제약을 우회한다.
- **직접 주입과 간접 주입** 같은 점은 둘 다 지시를 끼워 넣는다는 것.
다른 점은 누가 넣는가다. 사용자인가 자료인가. 뒤쪽이 훨씬 위험하다.
- **환각과 공격** 같은 점은 둘 다 이상한 답이 나온다는 것.
다른 점은 의도한 사람이 있는가다. 46장과 이 장이 나뉘는 이유다.
- **입력 검사와 권한 제한** 같은 점은 둘 다 방어라는 것.
다른 점은 확실성이다. 앞은 확률적이고 뒤는 결정적이다.
- **레드팀과 침투 시험** 거의 같은 것을 다른 층에서 부르는 이름이다.
앞이 모델 행동을, 뒤가 시스템 취약점을 본다.

## 지금 움직이는 것

주입을 모델 층에서 막으려는 시도에서 시스템 설계로 막는 쪽으로 옮겨 갔다. 프롬프트로 막는 방어가 계속 우회되면서, 뚫린다고 가정하고 권한과 격리로 피해를 제한하는 방향이 자리 잡았다. 그리고 남이 만든 도구 서버를 붙이는 위험이 새 문제로 올라왔다. 7장의 공급망 이야기가 이 층에서 반복되고 있고, 출처 확인과 서명 같은 장치가 논의되고 있다.
