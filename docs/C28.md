# 28장 작게 만들기

<sub>5부 언어 모델의 해부 · 표제어 43개 · 도해 4개</sub>

> **여는 지도** — 이 장의 낱말 마흔셋. 같은 모델을 싸게 돌리는 네 갈래

이 장은 이미 만들어진 모델을 더 싸게 돌리거나 더 싸게 고치는 방법들을 다룬다. 25장이 만드는 이야기였다면 여기는 다듬는 이야기다.

두 종류의 절약이 섞여 있다. 앞의 셋은 돌리는 비용을 줄이는 것이고, 마지막 하나는 고치는 비용을 줄이는 것이다. 목적이 다른데 같은 장에 있는 이유는 둘 다 파라미터를 덜 만지는 방법이라서다.

1장의 수 형식과 2장의 메모리 대역폭이 여기서 실제 값이 된다. 70억 개 값을 2바이트로 담으면 14기가바이트이고 1바이트면 7기가바이트다. 그 차이가 어느 기계에서 돌릴 수 있는지를 정한다. 44장의 비용 계산이 이 장의 선택 위에 서 있다.

## 한눈에 보기

| 무리 | 무엇을 줄이나 | 어디서 다시 쓰나 |
|---|---|---|
| 양자화 | 값 하나당 비트 수 | 41장, 44장, 50장 |
| 증류 | 모델 크기 자체 | 45장 데이터 |
| 가지치기 | 안 쓰는 파라미터 | 50장 하드웨어 |
| 효율 미세조정 | 고칠 때 만지는 파라미터 | 39장 특화 |
| 합치기 | 여러 모델을 한 벌로 | 51장 경향 |


## 표제어

### 수를 줄이기

#### 양자화

<sub>Quantization</sub>

**모델의 값을 더 적은 비트로 담아 메모리와 대역폭을 줄이는 일.**

<sub>관련어 정밀도(1장), 눈금, 학습 후 양자화, KV 캐시 양자화(24장), 메모리 대역폭(2장)</sub>

- **눈금** `Scale` — 양자화에서 실제 값과 정수 사이의 변환 비율. 이 값을 따로 저장해 두었다가 되돌릴 때 쓴다.
- **영점** `Zero Point` — 양자화된 정수에서 실제 0에 해당하는 값. 범위가 0을 중심으로 대칭이 아닐 때 필요하다.
- **대칭 양자화** `Symmetric Quantization` — 0을 중심으로 대칭 범위를 쓰는 방식. 영점이 필요 없어 계산이 단순하다.
- **그룹 단위 양자화** `Group-wise Quantization` — 가중치를 작은 묶음으로 나눠 묶음마다 눈금을 따로 잡는 방식. 정확도가 좋아지고 눈금 저장이 는다.
- **학습 후 양자화** `Post-Training Quantization, PTQ` — 학습이 끝난 모델을 그대로 줄이는 방식. 작은 보정 데이터만 있으면 되어 가장 널리 쓰인다.
- **양자화 인식 학습** `Quantization-Aware Training, QAT` — 학습 중에 양자화될 것을 반영해 학습하는 방식. 정확도가 덜 떨어지고 다시 학습해야 한다.
- **GPTQ와 AWQ** `GPTQ and AWQ` — 널리 쓰이는 학습 후 양자화 방법들. 앞은 가중치를 차례로 줄이면서 생긴 오차를 남은 가중치에 나눠 떠넘기고, 뒤는 활성값을 보고 중요한 가중치를 골라 덜 뭉개는 쪽으로 눈금을 잡는다.
- **보정 데이터** `Calibration Data` — 양자화 눈금을 정하려고 통과시켜 보는 소량의 데이터. 어떤 데이터를 쓰느냐가 결과에 영향을 준다.
- **이상치 채널** `Outlier Channel` — 값이 유난히 큰 특정 차원. 양자화 오차의 주범이라 따로 다룬다.
- **혼합 비트** `Mixed-Bit` — 층이나 부분마다 다른 비트 수를 쓰는 방식. 민감한 자리만 정밀하게 남긴다.

**정밀도를 줄일 때 실제로 달라지는 것**

| 정밀도 | 70억 모델 메모리 | 품질 | 쓰이는 자리 |

|---|---|---|---|

| 16비트 | 약 14기가바이트 | 기준 | 서버 기본 |

| 8비트 | 약 7기가바이트 | 거의 같다 | 널리 쓰임 |

| 4비트 | 약 3.5기가바이트 | 조금 떨어진다 | 개인 기기 |

| 3비트 이하 | 더 작다 | 눈에 띄게 떨어진다 | 실험적 |

실제로 필요한 메모리는 여기에 KV 캐시와 중간 값이 더해진다.
가중치만 계산해서 기계에 올린다고 생각하면 실행 중에 모자란다.
그리고 품질 저하는 과제마다 다르다. 대화는 잘 견디고 수학과 코드는 더 민감하다.

### 작은 모델에게 가르치기

#### 지식 증류

<sub>Knowledge Distillation</sub>

**큰 모델의 출력을 정답 삼아 작은 모델을 학습시켜 성능을 옮기는 방법.**

갈리는 자리 — 확률분포를 옮기는 좁은 뜻과 출력 텍스트로 학습시키는 넓은 뜻이 섞여 쓰인다

<sub>관련어 교사 모델, 학생 모델, 소프트 라벨, 합성 데이터(45장에서 다룬다)</sub>

- **교사 모델** `Teacher Model` — 지식을 넘겨주는 큰 모델.
- **학생 모델** `Student Model` — 배우는 작은 모델. 교사와 구조가 달라도 된다.
- **소프트 라벨** `Soft Label` — 정답 하나가 아니라 확률분포로 된 목표값. 부류 사이의 관계 정보를 담는다.
- **자기 증류** `Self-Distillation` — 같은 크기의 모델을 자기 출력으로 다시 학습시키는 방식. 성능이 오르는 경우가 보고된다.

### 잘라 내기

- **가지치기 (신경망)** `Pruning` — 기여가 작은 가중치나 구조를 잘라 내어 모델을 줄이는 일. <sub>관련어 구조적 가지치기, 희소성, 층 제거, 가지치기 (트리)(14장)</sub>
- **비구조적 가지치기** `Unstructured Pruning` — 개별 가중치를 0으로 만드는 방식. 압축률은 높고 실제 속도는 잘 안 오른다.
- **구조적 가지치기** `Structured Pruning` — 헤드나 채널이나 층을 통째로 없애는 방식. 그대로 빨라진다.
- **희소성** `Sparsity` — 값이 0인 비율. 하드웨어가 지원하는 특정 패턴의 희소성만 실제 속도로 이어진다.
- **층 제거** `Layer Dropping` — 중간 층 몇 개를 통째로 빼는 방식. 뒤쪽 층 일부는 빼도 성능이 크게 안 떨어진다는 관찰이 있다.
- **깊이 축소** `Depth Reduction` — 층 수를 줄여 모델을 작게 만드는 일. 폭을 줄이는 것과 성질이 다르다.
- **회복 학습** `Recovery Training` — 자르거나 줄인 뒤 짧게 다시 학습시켜 성능을 되돌리는 절차.

### 일부만 고치기

#### PEFT

<sub>Parameter-Efficient Fine-Tuning</sub>

**전체 가중치를 다 고치지 않고 작은 부분만 학습시켜 모델을 특정 용도에 맞추는 방법들의 총칭.**

<sub>관련어 LoRA, 어댑터, 미세조정, 검색 증강(33장에서 다룬다)</sub>

- **LoRA** `Low-Rank Adaptation` — 가중치 변화량을 두 개의 작은 행렬의 곱으로 표현해 그것만 학습시키는 방법. <sub>관련어 PEFT, QLoRA, 랭크(11장), 어댑터, 병합</sub>
- **QLoRA** `QLoRA` — 원래 가중치를 4비트로 양자화해 두고 그 위에 저랭크 학습을 얹는 방식. 큰 모델을 한 장의 가속기에서 미세조정할 수 있게 만들었다.
- **어댑터** `Adapter` — 층 사이에 작은 망을 끼워 그것만 학습시키는 방식. 추론에 층이 하나 더 붙어 조금 느려진다.
- **프롬프트 튜닝** `Prompt Tuning` — 프롬프트 자리에 학습되는 벡터를 넣어 그것만 배우게 하는 방식. 사람이 읽는 글자가 아니라 수의 묶음이라, 31장에서 사람이 프롬프트를 고쳐 쓰는 일과 이름만 닮았다.
- **접두 튜닝** `Prefix Tuning` — 각 층의 어텐션 앞에 학습되는 벡터를 붙이는 방식.
- **모델 병합** `Model Merging` 〔신조〕 — 여러 모델이나 어댑터의 가중치를 섞어 하나로 만드는 일. 다시 학습하지 않고 능력을 합치려는 시도다. <sub>생긴 때: 2023년 이후 널리 시도된다</sub>
- **어댑터 교체** `Adapter Swapping` — 같은 본체에 용도별 어댑터를 바꿔 끼우는 운영 방식. 41장의 서빙에서 다시 나온다.
- **미세조정** `Fine-tuning` 〔유동〕 — 이미 학습된 모델을 새 데이터로 더 학습시켜 특정 용도에 맞추는 일. <sub>갈리는 자리: 정렬 단계 전체를 가리키기도 하고 사용자 쪽 추가 학습만 가리키기도 한다 · 관련어 PEFT, SFT(26장), 파국적 망각(26장), 검색 증강(33장에서 다룬다)</sub>

**모델을 내 용도에 맞추는 네 가지와 고르는 기준**

| 방법 | 언제 맞나 | 비용 | 바뀌는 것 |

|---|---|---|---|

| 프롬프트 | 대부분의 경우 먼저 | 거의 없다 | 즉시 |

| 검색 증강 | 지식이 필요할 때 | 중간 | 문서만 갈면 된다 |

| 효율 미세조정 | 형식과 말투가 중요할 때 | 중간 | 모델 사본 |

| 전체 미세조정 | 아주 특수한 도메인 | 크다 | 모델 사본 |

위에서부터 시도하는 것이 순서다.
아래로 갈수록 비싸고, 모델이 새 세대로 바뀌면 다시 해야 한다.
그 재작업 비용을 안 세면 미세조정이 싸 보인다.

- **지식 편집** `Knowledge Editing` 〔신조〕 — 모델이 가진 특정 사실 하나를 다시 학습시키지 않고 고쳐 넣는 시도. 바뀐 사실을 반영하려고 전체를 다시 학습시키는 비용을 피하려는 것이고, 고친 것이 주변 지식을 망가뜨리는 문제가 남아 있다. <sub>생긴 때: 2022년 이후 연구 주제로 다뤄진다</sub>
- **가중치 평균** `Weight Averaging` — 같은 계보의 체크포인트들을 평균내어 하나로 만드는 방법. 여러 개를 다 돌리는 앙상블과 달리 추론 비용이 안 늘어난다.

### 작은 모델 자체

- **소형 언어 모델** `Small Language Model, SLM` 〔유동〕 — 작은 크기로 만든 언어 모델. 어디까지를 작다고 할지가 해마다 바뀌어서 기준이 흔들린다.
- **온디바이스** `On-Device` — 서버가 아니라 사용자 기기에서 모델을 돌리는 것. 지연이 없고 데이터가 안 나가며 크기와 전력에 제약이 있다.
- **엣지 추론** `Edge Inference` — 사용자 가까운 곳에서 추론을 돌리는 것. 8장의 엣지와 같은 발상이다.
- **모델 크기 계열** `Model Family` — 같은 방식으로 만든 여러 크기의 모델 묶음. 큰 것으로 데이터를 만들고 작은 것에 증류하는 구성이 흔하다.
- **용도별 소형 모델** `Task-Specific Small Model` — 한 가지 일만 하도록 작게 만든 모델. 그 일에서는 큰 모델보다 싸고 빠르며 정확할 수 있다.
- **모델 계층화** `Model Cascading` — 쉬운 요청은 작은 모델이, 어려운 것만 큰 모델이 처리하게 나누는 구성. 44장에서 비용 관점으로 다시 다룬다.
- **경량화** `Model Compression` — 이 장의 방법들을 묶어 부르는 이름. 무엇을 줄이는지에 따라 갈래가 나뉜다.
- **추론 엔진** `Inference Engine` — 양자화된 모델을 실제로 빠르게 돌리는 실행 환경. 어느 양자화 형식을 지원하는지가 선택을 제한한다.
- **형식 변환** `Format Conversion` — 모델 파일을 다른 실행 환경이 읽는 형식으로 바꾸는 일. 변환 과정에서 정밀도가 바뀌기도 한다.

## 자주 헷갈리는 짝

- **양자화와 가지치기** 같은 점은 둘 다 모델을 작게 만든다는 것.
다른 점은 무엇을 줄이는가다. 값의 비트 수인가 값의 개수인가.
- **증류와 미세조정** 같은 점은 둘 다 학습이라는 것.
다른 점은 목표다. 증류는 다른 모델을 흉내 내고 미세조정은 데이터를 배운다.
- **LoRA와 전체 미세조정** 같은 점은 둘 다 모델을 고친다는 것.
다른 점은 만지는 파라미터 수다. 결과물 크기가 천 배쯤 차이 난다.
- **미세조정과 검색 증강** 같은 점은 둘 다 모델을 내 용도에 맞춘다는 것.
다른 점은 지식이 어디 있는가다. 가중치 안인가 밖인가.
- **가지치기 (신경망)와 가지치기 (트리)** 같은 낱말이고 목적이 다르다.
앞은 작게 만들고 뒤는 14장에서 과적합을 막는다.

## 지금 움직이는 것

작은 모델의 성능이 빠르게 오르면서 이 장의 무게가 커졌다. 몇 해 전의 큰 모델과 비슷한 일을 지금의 작은 모델이 하고, 그 이유의 상당 부분이 큰 모델이 만든 데이터로 학습했기 때문이다. 동시에 4비트 아래 정밀도와 구조적 가지치기를 섞는 시도가 늘었다. 어느 조합이 표준이 될지는 아직 안 정해졌다.

## 더 볼 곳

여기서 줄인 모델을 실제로 돌리는 이야기가 41장이다. 비용 계산은 44장, 하드웨어 쪽 사정은 50장에서 다룬다. 미세조정 대신 검색을 쓰는 길은 33장이다.
