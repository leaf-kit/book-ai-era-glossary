# 25장 사전학습

<sub>5부 언어 모델의 해부 · 표제어 46개 · 도해 4개</sub>

> **여는 지도** — 이 장의 낱말 마흔여섯. 빈 모델이 언어를 배우기까지 여섯 자리

이 장은 아무것도 모르는 모델이 언어를 배우는 단계를 다룬다. 5부에서 가장 돈이 많이 드는 자리이고, 대부분의 사람이 직접 하지 않는 자리이기도 하다.

직접 안 해도 알아야 하는 이유가 있다. 모델의 성격이 거의 다 여기서 정해진다. 어떤 데이터를 얼마나 넣었는지가 무엇을 알고 무엇을 모르는지를 정하고, 언제까지의 데이터인지가 지식의 시점을 정한다. 26장의 정렬은 그 위에 얇게 덧입히는 층이다.

이 장에서 낱말이 두 무리로 갈린다. 얼마나 크게 만들지 정하는 이야기와, 실제로 돌리는 이야기다. 앞은 스케일링 법칙이고 뒤는 분산 학습이다. 둘 다 18장의 절차를 아주 크게 한 것이라, 그 장의 낱말이 그대로 쓰인다.

## 표제어

### 무엇을 얼마나 넣는가

#### 사전학습

<sub>Pre-training</sub>

**과제를 정하지 않고 대량의 텍스트로 다음 토큰을 맞히는 연습을 시켜 언어의 일반적인 능력을 갖추게 하는 단계.**

<sub>관련어 코퍼스, 다음 토큰 예측, 스케일링 법칙, 지식 컷오프, 정렬(26장에서 다룬다)</sub>

- **코퍼스** `Corpus` — 학습에 쓰는 텍스트 전체 묶음. <sub>관련어 데이터 혼합, 품질 필터, 웹 크롤, 데이터 수집(12장)</sub>
- **데이터 혼합** `Data Mixture` — 여러 출처를 어떤 비율로 섞을지 정한 것. 학습 도중에 비율을 바꾸는 방식도 쓴다.
- **품질 필터** `Quality Filter` — 쓸모없는 문서를 걸러 내는 절차. 규칙으로 거르기도 하고 작은 모델로 점수를 매겨 거르기도 한다. 양보다 이 단계가 성능을 더 가른다는 보고가 있다.
- **중복 제거 (코퍼스)** `Deduplication` — 같거나 거의 같은 문서를 걸러 내는 일. 안 하면 특정 문장을 통째로 외우고 성능도 떨어진다.
- **오염 제거** `Decontamination` — 평가에 쓸 문제가 학습 데이터에 들어가지 않게 걸러 내는 일. 완전히 하기 어려워 42장의 문제로 남는다.
- **지식 컷오프** `Knowledge Cutoff` — 학습 데이터가 어느 시점까지인지. 그 뒤의 일은 모른다. 다만 그 시점 직전의 최신 정보도 웹에 아직 안 퍼져서 잘 모르는 경우가 있다.
- **합성 데이터 (사전학습)** `Synthetic Data` 〔신조〕 — 모델이 만들어 낸 텍스트를 학습에 쓰는 것. 사람이 쓴 글이 모자라는 자리를 메우려는 시도이고, 45장에서 자세히 다룬다. <sub>생긴 때: 2023년 이후 사전학습에도 쓰이기 시작했다</sub>
- **데이터 벽** `Data Wall` 〔신조〕 — 쓸 만한 사람이 쓴 텍스트가 곧 바닥난다는 우려를 부르는 말. 실제로 언제 어떻게 부딪히는지는 추정마다 다르다. <sub>생긴 때: 2024년 무렵부터 널리 쓰인다</sub>

### 얼마나 크게 만들 것인가

#### 스케일링 법칙

<sub>Scaling Law</sub>

**모델 크기와 데이터 양과 계산량을 늘리면 손실이 예측 가능한 곡선을 따라 줄어든다는 경험적 관계.**

갈리는 자리 — 어느 판본의 비율을 기준으로 삼는지가 문서마다 다르고, 학습 최적과 추론 최적이 갈린다

<sub>관련어 계산 예산, 친칠라 비율, 손실 곡선, 창발</sub>

- **계산 예산** `Compute Budget` — 학습에 쓸 총 연산량. 대략 파라미터 수 곱하기 토큰 수에 비례한다.
- **친칠라 비율** `Chinchilla Ratio` 〔유동〕 — 계산 예산이 정해졌을 때 파라미터 수와 학습 토큰 수의 균형에 관한 기준. 이름은 이 결과를 내놓은 모델의 이름에서 왔다. 파라미터 하나당 스무 토큰 안팎이 자주 인용되는데, 조건에 따라 달라지는 값이다.
- **추론 최적화 학습** `Inference-Optimal Training` 〔신조〕 — 서비스 비용까지 고려해 작은 모델을 아주 오래 학습시키는 전략. 학습 최적 비율보다 훨씬 많은 토큰을 넣는다. <sub>생긴 때: 2023년 이후 널리 쓰인다</sub>
- **학습 토큰 수** `Training Tokens` — 학습에 실제로 흘려 넣은 토큰의 총량. 모델 크기와 함께 규모를 나타내는 두 축이다.
- **창발** `Emergent Ability` 〔유동〕 — 규모가 어느 지점을 넘으면 없던 능력이 갑자기 나타나 보이는 현상. <sub>갈리는 자리: 현상 자체가 실재하는지, 채점 방식의 산물인지가 갈린다 · 관련어 스케일링 법칙, 벤치마크(42장에서 다룬다), 지표(15장)</sub>

### 같은 예산을 어디에 쓸 것인가

- **전문가 혼합** `Mixture of Experts, MoE` — 피드포워드 부분을 여러 벌 두고 토큰마다 그중 몇 개만 골라 쓰는 구조. <sub>관련어 활성 파라미터, 라우터, 피드포워드(23장), 조밀 모델</sub>
- **활성 파라미터** `Active Parameters` — 한 토큰을 처리할 때 실제로 계산에 참여하는 파라미터 수. 전문가 혼합에서 전체 수와 크게 다르다.
- **조밀 모델** `Dense Model` — 모든 파라미터가 매번 다 쓰이는 보통 구조. 전문가 혼합과 대비해 부르는 이름이다.
- **라우터** `Router` 〔유동〕 — 어느 전문가에게 토큰을 보낼지 정하는 부분. 41장의 모델 라우팅과 이름만 같다.
- **부하 균형 손실** `Load Balancing Loss` — 전문가들이 고르게 쓰이도록 유도하는 추가 손실 항.
- **종횡비** `Aspect Ratio` — 모델의 폭과 깊이의 비율. 같은 파라미터 수를 어떻게 배분할지의 선택이다.
- **어휘 크기 선택** `Vocabulary Size Choice` — 어휘를 크게 잡으면 시퀀스가 짧아지고 마지막 층과 임베딩이 커진다. 다국어 성능과 직결된다.
- **자기 지도 목표** `Self-Supervised Objective` — 사람이 붙인 정답 없이 데이터 자체에서 문제를 만들어 내는 학습 목표. 다음 낱말 맞히기가 그중 하나이고, 이 방식이 있어서 인터넷 규모의 글을 쓸 수 있게 되었다.
- **인과 언어 모델** `Causal Language Model` — 앞의 낱말만 보고 다음을 맞히도록 배우는 모델. 23장의 마스킹으로 뒤를 못 보게 막는다. 여기서 인과는 원인과 결과가 아니라 시간 순서를 뜻한다.
- **마스크 언어 모델** `Masked Language Model, MLM` — 문장 중간을 가리고 그 자리를 맞히도록 배우는 모델. 앞뒤를 다 보므로 이해 과제에 강하고 문장을 이어 쓰는 데는 안 맞는다.

### 실제로 돌리는 절차

#### 다음 토큰 예측

<sub>Next Token Prediction</sub>

**앞의 토큰들을 보고 그다음에 올 토큰의 확률분포를 맞히는 과제.**

<sub>관련어 교차 엔트로피(13장), 인과 마스크(23장), 퍼플렉서티(10장), 자기회귀(21장)</sub>

- **학습 안정성** `Training Stability` — 며칠에서 몇 주짜리 학습이 안 터지고 도는 성질. 규모가 커질수록 어려워진다.
- **커리큘럼** `Curriculum` — 쉬운 데이터에서 어려운 데이터로 순서를 두는 방식. 학습 후반에 품질 좋은 데이터의 비중을 올리는 방식이 널리 쓰인다.
- **어닐링** `Annealing` 〔신조〕 — 쇠를 천천히 식혀 성질을 다듬는 열처리에서 온 이름이고, 학습 막바지에 학습률을 낮추면서 품질 좋은 데이터로 마무리하는 단계를 가리킨다. 성능이 눈에 띄게 오르는 경우가 보고된다. <sub>생긴 때: 2024년 무렵부터 이름이 쓰인다</sub>
- **중간 학습** `Mid-training` 〔신조〕 — 사전학습과 정렬 사이에 특정 능력을 보강하려고 넣는 추가 학습 단계. 부르는 이름이 아직 안 굳었다. <sub>생긴 때: 2024년 무렵부터 쓰이기 시작했다</sub>

### 여러 기계에 나눠 돌리기

**나누는 네 가지 방식**

| 방식 | 무엇을 나누나 | 통신이 드는 자리 |

|---|---|---|

| 데이터 병렬 | 배치를 나눠 각자 계산 | 기울기를 모을 때 |

| 텐서 병렬 | 한 층의 행렬을 쪼갬 | 층마다 매번 |

| 파이프라인 병렬 | 층을 구간으로 나눔 | 구간 경계에서 |

| 전문가 병렬 | 전문가를 기계마다 배치 | 토큰을 보낼 때 |

실제로는 넷을 섞어 쓴다. 한 노드 안에서는 통신이 빠르니 텐서 병렬을 쓰고,
노드 사이는 느리니 파이프라인이나 데이터 병렬을 쓴다.
어떤 조합이 좋은지는 상호연결 속도가 정한다. 50장에서 이 이야기를 다시 다룬다.

- **데이터 병렬** `Data Parallelism` — 같은 모델 사본을 여러 기계에 두고 배치를 나눠 처리한 뒤 기울기를 합치는 방식. 가장 단순하고 모델이 한 기계에 들어가야 한다.
- **텐서 병렬** `Tensor Parallelism` — 한 층의 행렬을 여러 기계에 쪼개 나누는 방식. 층마다 통신이 필요해 빠른 연결이 있어야 한다.
- **파이프라인 병렬** `Pipeline Parallelism` — 층을 구간으로 나눠 기계마다 맡기는 방식. 앞 구간이 끝나야 뒤가 시작되어 노는 시간이 생긴다.
- **시퀀스 병렬** `Sequence Parallelism` — 긴 시퀀스를 자리 기준으로 나눠 처리하는 방식. 긴 문맥 학습에서 쓴다.
- **버블** `Pipeline Bubble` — 파이프라인 병렬에서 앞 구간을 기다리느라 기계가 비어 노는 구간. 작은 조각으로 나눠 흘리면 줄어든다.
- **올리듀스** `All-Reduce` — 모든 기계의 값을 모아 합치고 다시 나눠 주는 통신 연산. 데이터 병렬에서 기울기를 합칠 때 쓴다.
- **통신 비용** `Communication Overhead` — 기계 사이 데이터를 주고받는 데 드는 시간. 규모가 커질수록 이것이 실제 병목이 된다.
- **체크포인트 저장** `Checkpointing` — 학습 도중 상태를 파일로 남기는 일. 큰 모델은 저장 자체가 오래 걸려서 얼마나 자주 할지가 판단거리다.
- **내결함성** `Fault Tolerance` — 기계 하나가 죽어도 학습이 이어지게 하는 성질. 수천 대를 몇 주 돌리면 고장이 반드시 나므로 필요하다.

### 잘 배웠는지 확인하기

- **퍼플렉서티** `Perplexity` — 모델이 다음에 올 것을 얼마나 갈피 못 잡는지 재는 값. 낮을수록 좋다. <sub>갈리는 자리: 비교 조건을 안 적으면 값이 아무 뜻이 없는데 그렇게 인용되는 경우가 많다 · 관련어 교차 엔트로피(13장), 손실 곡선, 벤치마크(42장에서 다룬다)</sub>
- **데이터 오염** `Data Contamination` — 평가에 쓸 문제가 학습 데이터에 들어가 있는 상태. 점수가 부풀려지고 발견하기 어렵다. 42장에서 다시 다룬다.
- **암기 측정** `Memorization Measurement` — 학습 데이터를 그대로 재생하는 정도를 재는 일. 48장의 권리 문제와 직결된다.
- **기본 모델** `Base Model` — 사전학습만 끝나고 정렬을 안 한 모델. 이어 쓰기는 잘하고 지시는 잘 안 따른다.
- **지시 모델** `Instruct Model` — 지시를 따르도록 추가 학습한 모델. 26장의 결과물이고, 실제로 쓰는 것은 대개 이쪽이다.
- **가중치 공개** `Open Weights` 〔유동〕 — 학습된 가중치를 내려받을 수 있게 공개한 것. 학습 데이터와 코드까지 공개한 것과 구별해야 하는데 둘 다 열려 있다고 불린다.
- **학습 재현** `Training Reproduction` — 같은 설정으로 다시 학습해 같은 결과를 얻는 일. 데이터와 순서와 하드웨어까지 맞아야 해서 사실상 어렵다.

## 자주 헷갈리는 짝

- **사전학습과 미세조정** 같은 점은 둘 다 가중치를 고친다는 것.
다른 점은 규모와 목적이다. 앞은 언어 전반을, 뒤는 특정 행동을 배운다.
- **파라미터 수와 활성 파라미터** 전문가 혼합에서 크게 갈린다.
앞은 메모리를, 뒤는 계산을 정한다.
- **퍼플렉서티와 벤치마크 점수** 같은 점은 둘 다 모델 품질을 나타낸다는 것.
다른 점은 무엇을 재는가다. 앞은 다음 토큰 예측, 뒤는 과제 수행이다.
- **데이터 병렬과 텐서 병렬** 같은 점은 둘 다 여러 기계를 쓴다는 것.
다른 점은 나누는 대상이다. 배치인가 행렬인가.
- **기본 모델과 지시 모델** 같은 점은 같은 사전학습에서 나왔다는 것.
다른 점은 지시를 따르는가다. 프롬프트를 적는 방식이 완전히 달라진다.

## 지금 움직이는 것

규모 경쟁의 축이 옮겨 갔다. 파라미터 수를 늘리는 경쟁에서 데이터 품질과 학습 토큰 수, 그리고 30장의 답하기 전 계산으로 무게가 이동했다. 같은 크기 모델의 성능이 해마다 크게 오르는데 그 원인의 상당 부분이 데이터 정리와 학습 후반 처리에 있다는 것이 공통된 관찰이다. 동시에 무엇을 넣었는지 공개하지 않는 관행이 굳어져서 바깥에서 원인을 확인하기가 어려워졌다.

## 더 볼 곳

여기까지가 언어를 배우는 단계다. 사람 말을 듣게 만드는 단계가 26장이고, 만들어진 모델을 작게 만드는 이야기가 28장이다. 분산 학습과 비용은 50장에서 다시 나온다.
