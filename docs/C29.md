# 29장 여러 감각

<sub>5부 언어 모델의 해부 · 표제어 47개 · 도해 4개</sub>

> **여는 지도** — 이 장의 낱말 마흔일곱. 아래에서 올라온 여러 갈래가 위에서 한 열로 합쳐진다

이 장은 글자 말고 다른 것을 같이 다루는 모델을 다룬다. 19장의 이미지와 21장의 생성 모델과 23장의 트랜스포머가 여기서 만난다.

기본 발상은 하나다. 다른 종류의 데이터도 결국 벡터 열로 바꿀 수 있으면 언어 모델이 그것을 토큰처럼 다룰 수 있다. 이미지를 조각내 벡터로 만들면 그 벡터들이 토큰 자리에 들어간다. 그래서 이 분야의 핵심 질문이 어떻게 벡터로 바꾸고 어떻게 이어 붙이는가가 된다.

실무에서 이 장이 중요해진 이유가 있다. 사람이 다루는 자료의 상당수가 순수한 텍스트가 아니다. 표와 그림이 섞인 문서, 화면 캡처, 손으로 쓴 것, 녹음 파일. 40장의 컴퓨터를 쓰는 에이전트도 화면을 봐야 해서 이 장 위에 선다.

## 한눈에 보기

| 무리 | 무엇을 다루나 | 어디서 다시 쓰나 |
|---|---|---|
| 인코더 | 각 감각을 벡터로 바꾸기 | 34장 검색 |
| 잇는 방식 | 언어 모델에 붙이는 두 방법 | 23장 크로스 어텐션 |
| 문서와 화면 | 실무에서 가장 많이 쓰는 자리 | 33장, 40장 |
| 음성 | 듣고 말하기 | 51장 경향 |
| 생성 | 이미지와 소리를 만들기 | 21장 확산 |


## 표제어

### 여러 감각을 다룬다는 것

#### 멀티모달 〔유동〕

<sub>Multimodal</sub>

**텍스트와 이미지와 소리처럼 종류가 다른 데이터를 함께 다루는 것.**

갈리는 자리 — 읽기만 하는 것부터 여러 감각을 통합 처리하는 것까지 같은 낱말로 부른다

<sub>관련어 비전 인코더, 이미지 토큰, 통합 모델, 시각 질의응답</sub>

- **모달리티** `Modality` — 데이터의 종류. 텍스트, 이미지, 음성, 영상 각각이 하나의 모달리티다.
- **교차 모달** `Cross-modal` — 한 종류로 다른 종류를 찾거나 설명하는 것. 글로 이미지를 검색하는 일이 그렇다.
- **모달 정렬** `Modality Alignment` — 서로 다른 종류의 데이터가 같은 공간에서 비슷한 자리에 놓이게 만드는 일.

### 각 감각을 벡터로

#### 비전 인코더

<sub>Vision Encoder</sub>

**이미지를 벡터 열로 바꾸는 부분.**

<sub>관련어 패치(19장), 이미지 토큰, 투영층, 비전 트랜스포머(19장)</sub>

- **이미지 토큰** `Image Token` — 이미지 조각 하나에 대응하는 벡터. 언어 토큰과 같은 자리에 놓인다.
- **투영층** `Projection Layer` — 인코더가 낸 벡터를 언어 모델의 차원과 표현에 맞게 옮기는 작은 층. 커넥터라고도 부른다.
- **동적 해상도** `Dynamic Resolution` 〔신조〕 — 이미지 크기와 내용에 따라 조각 수를 조절하는 방식. 작은 글자가 있는 문서에서 필요하다. <sub>생긴 때: 2024년 무렵부터 널리 쓰인다</sub>
- **타일링** `Tiling` — 큰 이미지를 여러 장으로 나눠 각각 처리하고 합치는 방식. 고해상도 문서를 다룰 때 쓴다.
- **대조 학습** `Contrastive Learning` — 짝인 것끼리는 가깝게, 짝이 아닌 것끼리는 멀게 벡터를 배치하도록 학습시키는 방법. <sub>관련어 임베딩 공간(22장), 비전 인코더, 이미지 임베딩(19장), 교차 모달</sub>
- **이미지 텍스트 쌍** `Image-Text Pair` — 이미지와 그 설명 글의 짝. 대조 학습의 재료이고, 권리 문제가 48장에서 다뤄진다.
- **캡션** `Caption` 〔유동〕 — 이미지를 설명하는 글. 학습 데이터로도 쓰고 모델이 만들어 내기도 한다.
- **오디오 인코더** `Audio Encoder` — 소리를 벡터 열로 바꾸는 부분. 파형을 시간과 주파수의 격자로 바꾼 뒤 처리하는 방식이 흔하다.
- **스펙트로그램** `Spectrogram` — 소리를 시간과 주파수의 격자로 나타낸 것. 이미지처럼 다룰 수 있어 19장의 구조를 쓴다.

### 언어 모델에 잇는 두 방법

**다른 감각을 언어 모델에 붙이는 방식**

| 방식 | 어떻게 잇나 | 장점 | 단점 |

|---|---|---|---|

| 토큰 이어 붙이기 | 이미지 벡터를 토큰 자리에 넣는다 | 구조가 단순하다 | 문맥을 많이 먹는다 |

| 크로스 어텐션 | 언어 쪽이 이미지 쪽을 본다 | 문맥을 덜 먹는다 | 구조가 복잡하다 |

앞쪽이 널리 쓰인다. 기존 언어 모델을 거의 안 고치고 붙일 수 있어서다.
대신 이미지 하나가 문맥 창의 상당 부분을 차지한다.
긴 문서를 이미지로 여러 장 넣으면 그것만으로 문맥이 찬다.

- **토큰 이어 붙이기** `Token Concatenation` — 이미지에서 나온 벡터를 텍스트 토큰 사이에 그대로 끼워 넣는 방식. 지금 가장 흔한 구성이다.
- **크로스 어텐션 방식** `Cross-Attention Fusion` — 언어 쪽이 질의를 만들고 이미지 쪽이 키와 값을 주는 방식. 23장의 크로스 어텐션이 여기 쓰인다.
- **멀티모달 지시 조정** `Multimodal Instruction Tuning` — 이미지와 질문과 답의 짝으로 지시를 따르게 만드는 단계. 26장의 절차를 이미지까지 확장한 것이다.
- **단계별 학습** `Staged Training` — 인코더와 투영층을 먼저 맞추고 그다음 전체를 함께 학습시키는 절차. 처음부터 다 같이 학습시키면 불안정하다.
- **인코더 동결** `Frozen Encoder` — 이미지 인코더를 고정하고 잇는 부분만 학습시키는 방식. 비용이 적고 이미지 이해의 상한이 인코더에 묶인다.

### 문서와 화면을 읽는 일

#### 문서 이해

<sub>Document Understanding</sub>

**표와 그림과 배치가 섞인 문서를 읽고 뜻을 파악하는 일.**

<sub>관련어 OCR(19장), 레이아웃 분석, 표 추출, 청킹(33장에서 다룬다)</sub>

- **레이아웃 분석** `Layout Analysis` — 문서에서 제목과 본문과 표와 그림의 영역을 구분하는 일.
- **표 추출** `Table Extraction` — 문서 이미지에서 표를 읽어 구조를 살려 내는 일. 병합된 칸과 여러 쪽 표에서 자주 틀린다.
- **문서 파서** `Document Parser` — PDF 같은 파일에서 텍스트와 구조를 뽑아내는 도구. 모델에 넣기 전 단계이고, 33장의 품질을 크게 좌우한다.
- **화면 이해** `Screen Understanding` 〔신조〕 — 화면 캡처에서 무엇이 어디에 있는지 파악하는 일. 40장의 에이전트가 이것 위에 선다. <sub>생긴 때: 2024년 이후 널리 쓰인다</sub>
- **시각 질의응답** `Visual Question Answering, VQA` — 이미지를 놓고 질문에 답하는 과제. 멀티모달 평가의 기본 형태다.
- **시각 접지** `Visual Grounding` — 말을 이미지의 실제 자리에 붙여 놓는다는 뜻이고, 말로 가리킨 것이 이미지의 어느 위치인지 찾아내는 일이다. 좌표를 내놓아야 해서 세는 일과 함께 약한 자리로 꼽힌다.
- **차트 이해** `Chart Understanding` — 그래프에서 값과 경향을 읽어 내는 일. 축과 눈금을 정확히 읽는 것이 어렵다.

### 듣고 말하기

- **음성 인식** `Speech Recognition, ASR` — 소리를 글자로 바꾸는 과제. <sub>관련어 화자 분리, 오디오 인코더, 음성 합성, 실시간 음성</sub>
- **음성 합성** `Text-to-Speech, TTS` — 글자를 소리로 만드는 과제. 말투와 감정과 속도를 조절하는 방향으로 발전했다.
- **화자 분리** `Speaker Diarization` — 녹음에서 누가 언제 말했는지 나누는 일. 회의록을 만들 때 필요하다.
- **실시간 음성** `Realtime Voice` 〔신조〕 — 말하는 도중에 끼어들 수 있는 수준의 지연으로 대화하는 방식. 글자로 바꿨다 되돌리지 않고 소리를 직접 다루는 구성이 나왔다. <sub>생긴 때: 2024년 이후 제품에 들어가기 시작했다</sub>
- **음성 대 음성** `Speech-to-Speech` 〔신조〕 — 글자 단계를 거치지 않고 소리에서 소리로 바로 가는 방식. 말투와 억양이 유지되고 지연이 줄어든다. <sub>생긴 때: 2024년 무렵부터 쓰인다</sub>
- **끼어들기** `Barge-in` — 모델이 말하는 도중에 사용자가 말을 시작하면 멈추는 동작. 실시간 대화에서 필요한 기능이다.
- **음성 복제** `Voice Cloning` — 짧은 녹음으로 특정 사람의 목소리를 흉내 내는 일. 48장의 권리와 사칭 문제와 직결된다.

### 만들어 내기

- **텍스트 투 이미지** `Text-to-Image` — 글로 설명하면 그에 맞는 이미지를 만드는 과제. 21장의 확산 모델이 주로 쓰인다.
- **이미지 편집** `Image Editing` — 기존 이미지를 지시대로 고치는 일. 어디를 바꿀지 지정하는 방식이 여럿이다.
- **인페인팅** `Inpainting` — 안쪽을 그려 넣는다는 뜻이고, 이미지에서 지우거나 가린 부분을 주변과 어울리게 채우는 일이다.
- **텍스트 투 비디오** `Text-to-Video` 〔신조〕 — 글로 설명하면 영상을 만드는 과제. 시간에 걸친 일관성이 어려운 자리다. <sub>생긴 때: 2023년 이후 급격히 발전했다</sub>
- **시간 일관성** `Temporal Consistency` 〔신조〕 — 영상에서 앞뒤 장면의 물체와 배경이 일관되게 유지되는 성질. 영상 생성의 주된 난제다. <sub>생긴 때: 2023년 이후 영상 생성 논의에서 쓰인다</sub>
- **통합 모델** `Unified Model` 〔신조〕 — 읽기와 만들기를 한 모델 안에서 하는 구성. 이미지를 토큰으로 만들어 언어와 같은 방식으로 생성하는 방향이다. <sub>생긴 때: 2024년 이후 시도가 늘었다</sub>
- **임의 입출력** `Any-to-Any` 〔신조〕 — 어떤 종류든 넣고 어떤 종류든 내는 모델을 가리키는 말. 목표를 나타내는 표현이고 실제 구현은 대개 제한적이다. <sub>생긴 때: 2023년 무렵부터 쓰인다</sub>

### 평가와 한계

- **멀티모달 벤치마크** `Multimodal Benchmark` — 이미지와 질문의 짝으로 능력을 재는 시험 묶음. 42장의 문제가 여기서도 그대로 나타난다.
- **환각 (시각)** `Visual Hallucination` — 이미지에 없는 물체나 글자를 있다고 말하는 현상. 46장의 환각이 이미지 쪽에서 나타난 형태다.
- **세기 오류** `Counting Error` — 이미지 속 개수를 잘못 세는 현상. 널리 관찰되는 약점이고 원인이 완전히 정리되지 않았다.
- **공간 관계 오류** `Spatial Reasoning Error` — 왼쪽과 오른쪽, 위와 아래 같은 관계를 틀리는 현상.
- **해상도 한계** `Resolution Limit` — 인코더가 다루는 해상도 때문에 작은 글자나 세부를 못 보는 문제. 타일링으로 완화한다.
- **토큰 비용 (이미지)** `Image Token Cost` — 이미지 하나가 문맥과 요금에서 차지하는 토큰 수. 해상도와 방식에 따라 크게 다르다.

## 자주 헷갈리는 짝

- **멀티모달과 통합 모델** 같은 점은 둘 다 여러 종류를 다룬다는 것.
다른 점은 만들기까지 하는가다. 읽기만 하는 것도 멀티모달이라 불린다.
- **OCR과 문서 이해** 같은 점은 둘 다 이미지에서 글자를 다룬다는 것.
다른 점은 배치와 구조까지 보는가다.
- **이미지 토큰과 텍스트 토큰** 같은 점은 둘 다 같은 자리에 놓인다는 것.
다른 점은 만들어진 방식이다. 앞은 인코더가, 뒤는 토크나이저가 만든다.
- **인코더 (비전)와 인코더 (트랜스포머)** 같은 낱말이고 역할이 비슷하다.
둘 다 입력을 표현으로 바꾼다. 다루는 데이터가 다를 뿐이다.
- **음성 인식과 음성 대 음성** 같은 점은 둘 다 소리를 다룬다는 것.
다른 점은 글자를 거치는가다. 안 거치면 억양이 유지되고 지연이 준다.

## 지금 움직이는 것

이미지를 읽는 능력이 기본 사양이 되었다. 따로 멀티모달 모델을 고르는 것이 아니라 대부분의 모델이 이미지를 받는다. 반면 만드는 쪽은 아직 별도 모델을 부르는 구성이 흔하다. 음성 쪽에서는 글자를 거치지 않는 구성이 제품에 들어가기 시작했고, 그 결과 대화의 지연 감각이 크게 달라졌다.

## 더 볼 곳

여기서 나온 화면 이해가 40장의 컴퓨터를 쓰는 에이전트로 이어진다. 문서 처리는 33장의 검색에서 실무 문제가 되고, 생성 쪽은 21장의 확산 모델이 바탕이다.
